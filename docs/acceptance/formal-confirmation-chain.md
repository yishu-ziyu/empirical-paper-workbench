## 1. 分工与交付边界

用户决定产品取舍；规范编写者提出可证伪的要求；执行 Agent 实现并自测；评审者独立读代码、核对证据和复跑关键路径。
执行者的“测试通过”和评审者的判断都不能替代实际用户路径。

本次只执行首批：从正式研究入口建立问题与设计，确认数据、样本和具体设定，得到第一条可追溯的真实估计。
不要求本批实现完整的普通研究结论账本、六章写作与导出闭环；那些是后续任务，不得在交付中称已完成。
OLS 可作为首个自动化用例，不代表将产品缩减为 OLS，也不将核心契约 §5 中尚待确认的完整 P0 范围改成已冻结。

协作顺序固定为：读取最新状态 → 保存接手基线 → 建立失败测试 → 实现 → 自测与浏览器验证 → 交接 → 独立评审。
默认沿用本地 checkout 串行接力。交接后执行者停止修改，评审者确认待评版本未变再开始。
评审结束前不继续堆下一批功能，也不由评审者悄悄改实现后把结果当成执行者原交付通过。

## 4. 首批要实现的用户路径

```text
确认研究问题 → 在同一会话提出/编辑/确认设计
→ 上传或选择数据候选 → 处理就绪 → 用户确认挂接
→ 运行方向核查并展示真实预览
→ 用户确认样本描述 → 用户确认具体分析设定
→ 用户启动估计 → 当前 run 结束 → 查看真实结果与来源
```

这是一条业务依赖链，不是必须新建十个页面。复用当前对话、面板和工作区；当前需要用户决定的动作应在可见位置，不藏进只读审计历史。
正常核查自动进行；明确需要确认的业务对象才要求用户确认。识别失败、执行失败、等待用户和研究成功不能合并成一个状态。

| 工作项 | 先读的实现 | 必须实现的结果 |
|---|---|---|
| 建立会话与问题 | `frontend/src/App.tsx`、`frontend/src/lib/workspace.ts`、`backend/routers/sessions.py:create_session` | 没有会话时复用 `POST /sessions` 建空会话，再提出设计。不能为了获得 session ID 强迫先上传，也不能只关空桌却宣称问题已持久化。刷新后回到同一研究。 |
| 设计提出与确认 | `backend/routers/design.py`、`backend/services/session_design.py` | 草稿可查看和必要编辑；用户确认后才获得设计锁。缺少草稿、失败或未确认时不授予下游权限。现有接口确实缺少必要编辑能力时才补最小接口，不另建平行设计对象。 |
| 同会话数据接入 | `backend/routers/attach.py:attach_dataset`、`backend/services/data_attach.py`、当前上传/恢复逻辑 | 已有设计的正式会话使用同会话 attach，不能调用建新会话的上传路径后丢掉原设计。保留现有 ingest、幂等与 run 恢复，不另建上传队列。 |
| 确认挂接 | `frontend/src/components/AttachPanel.tsx:confirmAttach`、`frontend/src/components/WorkbenchArtifact.tsx`、`backend/routers/attach.py:confirm_attach_dataset` | 接上真实请求。移除“点击即已挂接”的本地成功判定；已挂接由后端响应/回读 snapshot 决定。确认失败可重试；所有引导到挂接的入口都能看到可操作的同一动作。 |
| 方向核查与预览 | `backend/routers/outline.py:set_direction_endpoint`、`backend/facade/__init__.py`、`agent/engine/prewrite.py` | 依赖满足后核查，读取真实 Table 1 与执行公式；方向 run 正常停在预览不等于整个研究完成。后端直接调用也不能绕过正式设计和数据门槛。 |
| 两段确认与估计 | `backend/routers/outline.py:confirm_prewrite_endpoint`、现有 prewrite gate/preview、`workspace.ts:waitForTrackedRun` | 先确认真实样本，再确认对应设定。正确区分 `record_confirms` 的 200 与 `continue_estimate` 的 202；只有实际返回的 run 才进入统一等待。不能自动把两项确认都设为 true。 |
| 同步、恢复与防旧结果污染 | `workspace.ts`、`frontend/src/lib/runEvents.ts`、`frontend/src/lib/runSteps.ts` | 回读后端事实；正在运行时刷新重接同一 run。迟到的响应和事件不能写入另一会话或较新候选。首批新增入口重新提出设计/更换数据时不得沿用与旧对象绑定的确认。 |

实现前先找已存在的服务和组件；表中的符号是定位入口，不要求为了符合命名而新建同名函数。
后端应按实际对象与已有规则校验前置条件，不能仅禁用前端按钮；缺字段不能一律当 legacy 自动放行新正式会话。
对于不在本批路径中的历史兼容行为，不机械删除；须有明确适用边界和回归测试，不能变成新路径的绕过通道。

## 5. 不允许的替代方案

- 不删除确认、降低 hard block、伪造 `dataAttached` / confirmed / estimate / 用户批准来让测试变绿。`allow / confirm / forbid` 逐动作消费 #40 的既有判定；未知不写成通过或必然无效。
- 不为正式研究偷偷注入 Card 的设计、结果或正文；不以目录命中、题目相似或界面选了方法代替已确认设计。
- 不另造数据库、前端全局研究 stage、第二套 Run Engine；不继续把整条新流程无边界堆进 `workspace.ts`，新增职责应有清楚的边界且复用现有恢复入口。
- 不重设计全站、不替换编辑器、不扩数据源/多方法/光标演示；不改统计数值口径、租约安全要求、权限与凭据配置来迁就测试。
- 不修改冻结契约或减弱既有断言以迁就实现；不把测试改成跳过、不吞掉失败、不靠反复重跑挑一次绿色结果。
- 不 commit、push、merge、rebase、切分支、部署或触碰生产。依赖安装、付费模型调用、Pi/其他子 Agent 委派及不同执行方式，均需单独明确授权；本规范本身不是授权。

## 6. 应先失败的测试与验收矩阵

对已确认缺陷先新增能复现它的测试，保存修复前失败与修复后通过输出。若接手时问题已经修复，记录现状并补回归，不故意破坏代码制造 RED。
组件测试与整条 App 接线测试要分别覆盖；后者不能 mock 掉正在验收的 workspace 业务操作。

| 编号 | 场景与操作 | 必须观察到的事实 |
|---|---|---|
| C1 | 从空桌的可见入口建立问题、提出/编辑/确认设计 | 创建并保持同一 session；未确认是 draft；确认后响应和刷新 snapshot 一致。不能由浏览器测试偷偷 POST 确认代替缺失按钮。 |
| C2 | 对设计/挂接/样本/设定确认分别注入延迟、拒绝与网络失败 | 等待中只显示等待；失败不显示已确认、不推进下游；用户输入保留。请求可能已送达时先回读核对，不把未知当成成功或确定失败。 |
| C3 | 已有设计会话接入文件并确认挂接 | 会话 ID 与设计不丢；READY 只代表处理就绪，确认前 `dataAttached=false`，成功后为 true。PROCESSING/FAILED/CANCELLED 不得确认。 |
| C4 | 直接调用 API 尝试跳过草稿确认、数据挂接或必要预览 | 后端拒绝非法推进；不写确认标志、不入队估计。前端按钮 disabled 不算本项通过。 |
| C5 | 完成方向 run 后逐一确认 Table 1 与设定 | 展示后端真实样本和公式；仅确认样本不自动确认设定；两项未齐不启动估计；方向 run 成功停下时明确下一项确认。 |
| C6 | 记录确认返回 200、启动返回 202、排队拒绝、重复点击/重投 | 200 不拿空 run ID 等待；202 跟踪返回的 run；同一投递凭证不重复创建估计。队列/会话忙提示与后端事实一致，不能假完成。 |
| C7 | 每次确认后刷新；上传/方向/估计运行中刷新 | 恢复同一会话、确认对象与活动 run；不重新上传、不自动再确认、不创建多余 run；事件与持久终态一致。 |
| C8 | 新增流程中换候选、重提设计、切会话，随后旧响应到达 | 旧确认不沿用到新对象；旧响应不覆盖当前对象；旧运行不污染当前披露。既有历史不删除。纯语言/布局变化不触发研究变更。 |
| C9 | 分别输入明确阻断、风险、未知的诊断事实 | 按 #40 的逐动作许可处理；forbid 不可越，confirm 有明确确认与留痕，allow 不凭空新增闸门；没有事件不造进度。 |
| C10 | 非 Card 的 OLS 用例走完可见确认链并执行 | 使用真实统计执行，不伪造系数；结果可追到本次数据、设定、run 与执行代码。事先声明比较容差，复跑核对主系数、样本数及口径，不能只断言存在数字。 |
| C11 | 桌面 1440×900 与小屏 320×568，键盘完成关键确认 | 所有关键动作可见可达；弹层可滚动且不越界；截图、DOM/焦点、请求与 snapshot 支持结论，无相关未解释控制台错误。实际读取截图，不能只生成文件。 |
| C12 | 跑既有 Card、上传恢复、渐进运行与 #40 回归 | 已有入口与冻结语义不退化。新正式路径不是通过误归类成教学/legacy 来过门。 |

本批至少完成 C1–C12；任何缺项写清原因和影响，交付状态只能是待补证据/受阻，不能宣称完整通过。
使用模拟事件的测试可验证故障处理；浏览器主路径必须连接隔离的真实 backend + runner + frontend，不能整套 route.fulfill 出批准与估计结果。
验收数据优先使用来源明确且已获准使用的非 Card CSV。没有获准真实数据时，可用明确标注的合成 CSV 验证接线与实际计算；报告必须标为合成数据链路，不能替代核心产品契约中的真实数据验收。
未授权的真实模型调用不执行；使用 mock 的模型环节必须列明，mock 的研究内容不能计作模型质量或完整论文验收。

## 7. 验证与证据

先跑受影响测试，再运行仓库质量门：`make test`、`cd frontend && npm run lint && npm run build`、`git diff --check`。
变更 API 时按 Makefile 的既有生成入口同步 OpenAPI 与客户端类型并通过 drift 检查，不手改生成类型。
前后端和 runner 在隔离环境启动后运行 `make verify`；它只证明对应健康检查，仍须另外跑 C1–C11 的浏览器链路。

本机已验证过 Playwright 截图 → `DevSpace.read` 读取 PNG 的通道；不需要为此默认启动另一个模型 Agent。
检查项目已有浏览器脚本并优先复用。使用独立端口、临时数据库和测试存储，不连接用户日常数据库、不占用或结束别人的服务。
截图、trace、请求摘要、日志放仓库外专用证据目录；自动化回归用例留在项目既有测试目录。
保存命令、退出码、时间、代码指纹、session/run ID 与证据路径。脱敏，不保存 Authorization、cookie、密钥、用户原始数据和私人论文正文。
收尾只停止自己启动的进程；保留能重跑的脚本/命令与必要的去敏证据。
VoiceOver 的真实播报单列为未验/已验项目；属性或 DOM 检查不等于真人读屏体验，也不因这项未验而放弃可执行的截图与键盘验证。

## 9. 独立 review 与下一批

评审者先核对接手/交付指纹，再读冻结要求、实际增量 diff 和相关上下游代码；不以执行者结论或旧的全绿记录代替复核。
重点看确认权归属、同会话数据接入、后端防越过、异步旧响应、幂等恢复、#40 许可语义，以及是否又新增重复状态和难维护分支。
对高风险测试独立复跑并阅读截图/网络/snapshot；证据与文件指纹不一致时要求重新对齐。修复后重跑受影响项，不机械重复无关全套检查。

评审结论分三类：`ACCEPT`（本批满足要求）、`REJECT`（存在可复现违约/回归）、`NEEDS EVIDENCE`（代码或证据不足以判断）。
每项问题需给优先级、可观察影响、文件/函数、复现条件、最小修复和回归测试；P1 或硬规则违约未修复不得 ACCEPT。
规范本身不授权自动修复、合并或发布。是否进入下一批、接受范围外风险由用户决定。

后续顺序：普通研究的证据采用/结论批准与失效传播 → 六章文稿及导出一致性 → 在闭合业务上细化渐进布局。
这些不是本批完成项；完整 P0 的数据范围、方法和真人验收仍按核心产品契约的待确认项处理。
