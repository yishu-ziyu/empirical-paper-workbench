# Peer Spec: 全自动论文机产品化

> 日期：2026-06-22
> 评审人：Claude (Sonnet 4.6)
> 被评审文件：`plan/spec.md`

## 评审总结

Spec 文档完整，覆盖了 5 条验收标准和 3 条 golden journey。整体质量良好，但有 3 个需要改进的地方。

## 详细评审

### AC1: Runtime 统一

**状态**: ✅ 通过

**优点**:
- 验收标准具体可验证（dry-run/execute/resume/status 四种模式）
- Human checkpoint 不可绕过——这是关键的安全约束
- 产物已存在时自动跳过——幂等性设计正确

**建议**:
- 建议增加一条验收标准：`runtime/cli.py` 能处理 registry.json 中缺少字段的情况（容错性）

### AC2: 跨题验证

**状态**: ✅ 通过

**优点**:
- 选定了具体题目（CFPS 最低工资消费效应）
- 验收标准明确（paper.pdf + tables/ + figures/ + repro_report.md）

**建议**:
- 建议增加一条验收标准：跨题验证必须在 **3 次尝试内** 成功（避免无限调试）

### AC3: 高质量工作台

**状态**: ⚠️ 有条件通过

**问题**:
- 验收标准中提到"纯静态 HTML"，但当前产品壳是 React + FastAPI
- 建议改为：工作台优先嵌入 React 产品壳，纯静态 HTML 作为 fallback

**建议**:
- 增加一条验收标准：工作台必须在 390px 移动端正常显示（响应式）

### AC4: StatsPAI DID 适配器

**状态**: ✅ 通过

**优点**:
- 验收标准具体（事件研究图 + 主回归 + 异质性）
- 产物路径明确（tables/table2_did.csv + figures/event_study.png）

**建议**:
- 建议增加一条验收标准：DID 适配器必须输出 `model_log.md`（记录公式、样本量、R-squared）

### AC5: 证据审计

**状态**: ✅ 通过

**优点**:
- 每个 claim 自动绑定真实数据——这是核心安全约束
- 缺失证据时标记 `needs_evidence` 而非静默跳过——正确

**建议**:
- 建议增加一条验收标准：证据审计必须在 **10 秒内** 完成（性能约束）

## Golden Journeys

### Journey 1: 新题目从零到论文

**状态**: ✅ 通过

**评价**: 完整覆盖了 10 步 workflow，验收标准清晰。

**建议**:
- 建议增加一条失败路径：如果某步失败，系统必须输出具体的 failure code 和修复建议

### Journey 2: 工作台可视化

**状态**: ✅ 通过

**评价**: 交互流程清晰，验收标准可验证。

**建议**:
- 建议增加一条验收标准：工作台必须在 **无网络** 环境下正常显示（离线可用）

### Journey 3: 中断恢复

**状态**: ✅ 通过

**评价**: 幂等性和恢复机制设计正确。

**建议**:
- 建议增加一条验收标准：resume 后必须跳过已完成步骤，不重复执行

## 总体评价

**质量**: 良好（8/10）

**优点**:
- 5 条验收标准具体可验证
- 3 条 golden journey 覆盖核心用户路径
- 产物路径明确，无歧义

**需要改进的地方**:
1. 增加容错性验收标准（registry.json 缺少字段、3 次尝试限制）
2. 工作台优先嵌入 React 产品壳，纯静态 HTML 作为 fallback
3. 增加性能约束（证据审计 10 秒内完成）
4. 增加离线可用性约束
5. 增加失败路径验收标准

**结论**: Spec 可以通过，但建议在 dev phase 开始前补充上述 5 条验收标准。
