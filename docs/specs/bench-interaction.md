# 操作台交互：数字先于正文

设计来源见 `docs/specs/design-sources.md`。
Notion 已实载；本机货架也读了。
旧「仪器在暗房里 + 蜡笔红」不再当规范。
发动机：`docs/specs/paper-engine.md`。

本页只写人看见什么、点什么、机器已经有什么。

## 一句结论

人只做三件事：上传 CSV、填方向、批章节。
机器在方向提交后必须先交出识别、主表、稳健性戳、文献列表。
没有这些东西时，对应章节的「写」是灭的，不是点了再编。

这是写论文的桌，不是暗房仪器展。
颜色只表达意义：绿是可点的下一步，金是写不了，红不当品牌。


台面纸 `#f4efe4`，浅壳 `#f1f0ed`，字 `#181515`。
当前章和主按钮用绿 `#2f6b4f`。
不必填满整屏。
邻近的东西挨着放（标签贴输入）。

读数台就是 Notion 的「展示工作步骤」：先看见主张、星、主表、文献，再允许写。

## 人走的顺序（和发动机一致）

```
上传 CSV
   ↓
清洗（机器，可停）
   ↓
四问 + 方法列
   ↓
一次预写：识别 → 估计 → 稳健 → 文献 → 标题 → 大纲
   ↓
读数台上出现：主张 / 星或无星 / 主表那一行 / 稳健戳 / 文献来源
   ↓
按章点写（点 type，不是「继续生成整篇」）
   ↓
审：看得见是真审还是假审；另造表则这一稿作废
   ↓
导出
```

文献不是人先去检索的一站。
方向提交后机器已经检索过。
旅程第 2 站「文献」只是读数，不是一张空白检索表。

人随时能接管：不写、回滚、改方向。
机器是助手，不是老板。

## 方向表

四问一直在：问题、因变量、自变量、控制、方法、模板。

方法变了，多出来的列才出现（后端门已经吃这些键）：

- OLS：不再多列。无星按相关写，这是成功。
- DiD：时间列、个体列、队列列 `first_treat_col`。
- IV：工具变量。
- RD：running、cutoff。
- SCM：单位、处理时点。

方法选择只承诺发动机真会跑的五类。
38 个名字如果还留着，必须映射到这五类，不能让人以为选了 Causal Forest 就会跑森林。

## 读数台（方向返回之后立刻有）

用 mono 标签，不要彩虹卡片。

- `CLAIM` 关联 / 有保留的因果
- `STAR` 0–3，或 `NONE`（OLS）
- `TABLE` 就是 `estimate.treatment_row`，不是模型再画的表
- `ROBUST` 已跑 / 可见降级原因
- `LIT` `crossref` / `mock` / `mock_degraded`
- `BLOCK` 开写失败码，告警色，不是蜡笔红

0 星：大纲不出现，写章全灭，写「先改设计」。

综述章的引用必须能点回本次文献列表。
编出来的来源不算引用。

## 写章

不要再走「确认大纲 → WebSocket 整篇往下冲」。
发动机已经把章节从预写图里拿掉。

每一章：点 type → `POST /generate-chapter` `{ chapter: { type } }`。
409：读数台亮 `BLOCK`，纸上不出现假正文。
200：纸上是这一章；结果章文末是主表。
评审 JSON 失败：仪表写 `review_source=mock_fallback`，不要看起来像真审过。
另造第二张 `| 变量 | 系数 | SE | p |`：这一稿回炉。

主路径（上传、填方向、批章节、导出）在 AI 挂掉时仍要能看见已有数字和已写正文。

## 不要做

- 用正文出现代表估计完成。
- 让人在没表时写结果章。
- 六色 badge 当进度（蓝紫绿橙红灰）。
- 卡片阴影、多 accent、蜡笔红当品牌。
- 把整站铺成暖墨暗房。
- 把文献做成需要人先搜完才能交方向。
