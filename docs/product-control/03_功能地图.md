# 03 功能地图

## 主线模块

这些模块构成第一版作品集 MVP。没有这些，产品路径不完整。

| 模块 | 用户问题 | 产品输出 | 第一版状态 |
|---|---|---|---|
| 研究入口 | 我从哪里开始？ | ResearchIntent / TaskBrief | 必须做 |
| Agent 任务队列 | 谁在帮我做什么？ | SupervisorPlan / AgentTaskQueue | 必须做 |
| 数据与变量 | 数据能不能支撑题目？ | DatasetProfile / VariableRoleCandidate | 必须做 |
| 方法设计 | 该用什么实证方法？ | DesignSpec / MethodGate / RunPlan | 必须做 |
| 执行实验 | 结果是不是跑出来的？ | MethodExecutionResult / logs / tables | 必须做 |
| 结果与草稿 | 哪些结论能写？ | FindingCandidate / ResearchReport / Draft | 必须做 |
| 审阅与导出 | 能不能交付？ | VerifierReport / ExportPreflight | 必须做 |

## 支撑模块

这些模块很重要，但不应该喧宾夺主。

| 模块 | 作用 | 第一版边界 |
|---|---|---|
| Skill Registry | 给 Agent 提供方法和任务能力 | 先做内部索引和选择理由 |
| Journal Skill | AER-like / 顶刊标准检查 | 用户选择高标准时启用 |
| Method Knowledge Base | 沉淀 OLS/DID/IV/RDD/PSM/DML 等规则 | canonical 规则必须人工 review |
| Evidence Registry | 统一管理证据、表格、代码、引用 | 所有可写入论文内容必须绑定 |
| Trace Learning | 记录 bad case 和修复经验 | 用于改进任务队列和门禁 |
| Provider Registry | 管理 Codex、OpenAI、MiniMax 等模型入口 | 第一版优先 Codex 本地测试 |

## 暂缓模块

这些不是不做，而是不要在作品集 MVP 前阻塞主线。

| 模块 | 暂缓原因 |
|---|---|
| 完整云端多租户 | 当前需要先把本地路径跑通 |
| 复杂权限系统 | 第一版用户是本人和少数熟人 |
| 全量 CNKI 自动化 | 受登录、版权和浏览器状态影响 |
| 多人协作编辑器 | 当前核心问题是研究链路，不是协同写作 |
| 完整支付和订阅 | 没有产品验证前不做商业化外壳 |
| 大规模模板市场 | 先证明一个工作流能跑通 |

## 功能取舍原则

如果一个功能不能帮助用户完成以下任一动作，就不进入 MVP：

- 明确研究问题。
- 找到可用数据。
- 判断变量角色。
- 选择实证方法。
- 执行并记录结果。
- 判断结果能否写进论文。
- 生成可审阅产物。

## 当前最该补的功能

从作品集 MVP 看，优先级是：

1. 一条固定题目的可演示闭环。
2. LLM Supervisor 在关键节点的真实介入说明。
3. Evidence Registry 阻断无证据正文。
4. UI 上清楚显示当前阶段、下一步、阻塞原因。
5. 一份产品案例页，把问题、方案、流程、截图、验证结果讲清楚。
