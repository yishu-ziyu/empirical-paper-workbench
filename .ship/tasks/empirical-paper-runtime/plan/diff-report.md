## 解决详情

### 采纳的差异（8 条）

1. **容错性验收标准**：在 AC1 中增加 "runtime 能处理 registry.json 中缺少字段的情况"
2. **跨题验证尝试限制**：在 AC2 中增加 "跨题验证必须在 3 次尝试内成功"
3. **工作台实现方式**：修改 AC3 为 "工作台优先嵌入 React 产品壳，纯静态 HTML 作为 fallback"
4. **移动端响应式**：在 AC3 中增加 "390px 移动端正常显示"
5. **DID 适配器产物**：在 AC4 中增加 "产出 model_log.md"
6. **离线可用性**：在 AC3 中增加 "无网络环境下正常显示"
7. **失败路径**：在 Journey 1 中增加 "如果某步失败，系统必须输出具体的 failure code 和修复建议"
8. **Resume 幂等性**：在 Journey 3 中增加 "resume 后必须跳过已完成步骤，不重复执行"

### 不采纳的差异（1 条）

6. **证据审计性能（10 秒内完成）**：
   - **原因**：性能约束应该在性能测试中验证，不应该在 spec 中硬编码时间限制
   - **替代方案**：在 QA phase 增加性能测试，验证证据审计在合理时间内完成

## 更新后的 Spec

差异已全部解决，更新后的 `spec.md` 包含：

- 所有验收标准都是可验证的（通过测试或手动检查）
