# ADR 0012 — 旅程呈现：用户动作层与引擎阶段层

- **Status:** Accepted（决策点 1/2/3 于 2026-08-31 奕枢拍板，已实施；决策点 4 另议）
- **Date:** 2026-08-31
- **Supersedes:** —（ADR-0010 的引擎层 8 站经本 ADR 确认继续有效）
- **Related:** ADR 0010（一个网页产品 / Journey 8 站）、`devlog-2026-08-18.md`

## Context

### 1. 两套流程不是矛盾，是两个抽象层级

`agent/graph.py:3-8` 的模块文档字符串明确了分层：

> 本图**只覆盖预写段**（upload → clean → set_direction → identification →
> estimate∥literature → robustness∥citation → title → outline）。章节生成 /
> 评审 / 导出等后续阶段**不在图中**，由 backend Facade 以 HITL 单点调用驱动。

由此，项目里存在两个性质不同的流程：

| | 引擎阶段层 | 用户动作层 |
|---|---|---|
| 数量 | 8 站（ADR-0010 line 24/40） | **4 步** |
| 谁驱动 | LangGraph 自动跑 + HITL 单点调用 | 用户 |
| 依据 | ADR-0010（Accepted，08-16） | `devlog-2026-08-18`（devlog，非 ADR） |
| 用户需要理解吗 | 不需要 | 需要 |

**用户动作层的 4 步可以从代码反推验证：**

`bench.journey = '上传 → 方向 → 估计 → 按章写'`（`i18n.tsx:353`）与代码的中断点精确吻合：

1. **上传** — `upload_data` 节点
2. **方向** — `graph.py:42-47 route_after_clean`：无 `research_direction` 则停
3. **估计** — `graph.py:56-57 route_after_identification`：0 星则 `hitl_pause`；否则自动跑 estimate∥literature
4. **按章写** — 不在图中，由 Facade HITL 单点调用驱动

**结论：`bench.journey` 的 4 步是准确的。ADR-0010 的 8 站也是准确的。它们描述的是不同的东西。**

### 2. 真正的问题：UI 没有分层，两套被并列显示

当前 UI 里有五处流程呈现，分属两层，**但没有任何一处声明自己属于哪一层**：

**用户动作层（4 处表述）**

| # | 位置 | 内容 | 状态 |
|---|------|------|------|
| 1 | `App.tsx:406-411` → `i18n.tsx:353` `bench.journey` | 4 步静态字符串 | 活，**永不变化** |
| 2 | `App.tsx:450-462` → `StepTimeline` | 4 步动态 | 活，10 props 驱动 |
| 3 | `GuidePage.tsx:144` → `i18n.tsx:84` `guide.badge` | 4 步，Landing hero 胶囊 | 活 |
| 4 | `GuidePage` how-it-works → `i18n.tsx:160-162` | 3 步 | 活，需滚动到另一 section |

**引擎阶段层（2 处表述）**

| # | 位置 | 内容 | 状态 |
|---|------|------|------|
| 5 | `App.tsx:587` → `paperPath.ts:3-12` | 8 站英文标识符 | 活，用户看不懂 |
| 6 | `progress.py:39-48` → `JourneyTimeline` | 8 站 | **从未挂载，见下** |

### 2.4 #6 的准确病史：挂载 → 有意卸载 → 九天后同位置重建

> **本节曾因取证方法错误写过一版错误结论（「从未挂载」），已撤回。**
> 错因：`git show <commit>:frontend/src/App.tsx` 在旧 commit 上返回空时被误读为
> 「文件里没有」。正确做法是先用 `git ls-tree -r --name-only <commit>` 确认路径存在，
> 再取内容——本节的表格即用此法重查后的结果。

逐 commit 检查 `App.tsx` 中 `JourneyTimeline` 的出现次数：

| commit | 日期 | 动作 | `App.tsx` 挂载? |
|---|---|---|---|
| `bc8c612` | 08-17 | 引入并挂载 | **是（出现 2 次）** |
| `20a3c57` | 08-18 | **有意卸载**（import + JSX 双删） | 否 |
| `ac6d2df` | 08-27 | 组件文件仍被修改 | 否 |
| `9b00ca2` | 08-29 | 组件文件 −100 行，被 `StepTimeline` 取代 | 否 |

卸载的**有意性**有用户自己的文字为证——`docs/notes/devlog-2026-08-18.md:27`：

> 右栏不再摊八站旅程，写出一章后这里是评审。

而重建发生在九天后：`e4484fb`（08-27）把 `PAPER_NODES` 的 8 个英文节点
装回了 **08-18 特意清空的同一个右栏位置**（`App.tsx:585` `agent={`），
没有任何一次提交对照过 08-18 的卸载记录。

**所以 #6 的性质是：一次干净且有意的删除，九天后被无意的重建覆盖。**
组件文件、后端契约（`/journey` 路由）、i18n 文案三者在卸载时都没删，
重建时也都没人再提起——13 天里没有任何机制提示「这个位置曾经清空过」。

后果：

- **层内冲突一（同屏）**：#1 与 #2 **同屏并存**（同一 JSX 分支，相隔 40 行），一个静态一个动态，说同一件事的两个版本
- **层内冲突二（重复 key）**：#1 `bench.journey` 与 #3 `guide.badge` **一字不差**（均为「上传 → 方向 → 估计 → 按章写」），却是 `i18n.tsx` 里两个独立条目（353 / 84，英文件 880 / 622）。改一处不会同步另一处
- **层内冲突三（跨屏）**：Landing 页 #3 说 4 步、#4 说 3 步，用户滚动即可看到两个版本
- **层间混用**：#5 把引擎阶段层的代码标识符（`upload_data`、`export_docx`）直接暴露给用户
- **唯一有 ADR 依据的实现（#6）从未挂载**

### 3. 为什么这件事没被发现

ADR-0010 管住了后端（`progress.py` 的 `canIntervene = {0,2,3,5,6}` 与 ADR line 40 **逐位一致**），
但**没有覆盖 UI 层的流程呈现**。08-18 的「课设」定位调整改造了 UI（#1、#4），未走 ADR，
因此没人知道要同步或删除按 ADR-0010 实现的 #5。

1274 个测试全绿，其中包含 11 个验证未挂载组件 `#5` 的测试，让这件事在验收时不可见。

## Decision

> 2026-08-31 奕枢对照「工作台现状图 + 右栏三方案对比图」拍板（两图一问流程）。

### 决策点 1：用户动作层 → **删静态行，进度完全由 StepTimeline 表达**

- `App.tsx` 中栏顶部的静态行「上传 → 方向 → 估计 → 按章写」（`bench.journey`，`data-testid="product-journey"`）**已删除**
- 当前进度完全由 `StepTimeline` 动态卡表达，同屏只讲一套话
- `bench.journey` key 保留（Landing Page 的 `guide.badge` 已于同日合并到该 key）

### 决策点 2：引擎阶段层 → **B 汉化分层（PaperPath 保留，说人话，可展开）**

- 右栏 `PaperPath` 8 站保留，`i18n.tsx` 的 `path.*` 8 条已从裸标识符改为中文/英文人话
  （上传数据 / 清洗数据 / 设定方向 / 设定曲线 / 生成大纲 / 撰写 / 审批章节 / 翻译代码 / 导出文档）
- 文案走**节点视角**（引擎实际做什么），不复用 `journey.step1-8`（那是另一套 8 站的用户视角，语义不对应）

### 决策点 3：ADR-0010 的 8 站 → **仍然有效**

- B 方案隐含确认：后端 `progress.py` 8 站契约与 `canIntervene {0,2,3,5,6}` 不动
- 引擎阶段层（8 站）与用户动作层（4 步）是两个抽象层，本不冲突——
  `agent/graph.py:3-8` 证实图只覆盖预写段，后续由 Facade HITL 单点驱动

### 决策点 4：`spec.py:86` 的 `cn_journal` 默认模板 → **另议**

- 未在本轮拍板。现状：默认值与 08-18 devlog「不是期刊投稿器」的定位声明冲突，但 devlog 无 ADR 地位

## Consequences

随决策 1/2/3 同日实施（前端 vitest 260 passed / tsc 通过）：

1. **同源 bug 修复**：`paperPath.ts:95-96` 此前 `translate_code` 与 `export_docx` 同源派生自
   `canExport`，永远同步跳变。现新增 `hasExported` 信号（`workspace.ts`，导出成功后置 true），
   解耦为：未导出时 `translate_code=pending`（代码在导出时才生成，不再谎报进行中）、
   `export_docx=active`；导出成功后两者 `completed`
2. **`App.test.tsx`** 断言反转：`product-journey` 从「存在四步文案」改为「不再存在」
3. **i18n 去重**：`guide.badge`（中英两条）已删除，统一到 `bench.journey`
4. `JourneyTimeline` 死链（组件 + 后端 `/journey` 路由 + `journey.step{N}` i18n）**保留未删**——
   决策 3 确认引擎层有效后，它是「8 站的用户视角文案」，未来做决策点 2 的展开层时可复用；
   是否接线或删除留待后续

## 备选方案（Considered，已被上方 Decision 取代）

### 决策点 1：用户动作层收敛到几处

当前有 **4 处表述**（#1 静态 4 步 / #2 动态 4 步 / #3 Landing 4 步 / #4 Landing 3 步）。

| 选项 | 代价 |
|---|---|
| 收敛到 #2（动态）一处 | 删 `App.tsx:406-411`、合并 `guide.badge` 进同一 key、统一 Landing 站数。最干净，但 4 处文案与测试都要动 |
| 保留 #1（静态）+ 删 #2 | 删 `StepTimeline` 及其测试；进度不再变化，用户失去当前状态反馈 |
| 两处都留但分工 | 需明确 #1 为"总览"、#2 为"当前状态"——但文案重复，用户难分辨 |
| **只解决 key 重复** | 最小动作：把 `guide.badge`(84/622) 与 `bench.journey`(353/880) 合并为一个 key。不影响任何视觉，但消除"改一处漏一处" |
| Landing 站数是否统一 | #3 说 4 步、#4 说 3 步，同页滚动可见。需选定一个 |

### 决策点 2：引擎阶段层要不要给用户看

| 选项 | 代价 |
|---|---|
| **折叠**（只给用户看 4 步） | 引擎 8 站收进日志/详情页。最符合「Apodex 式自主」方向，但用户失去过程可见性 |
| **分层展示**（默认 4 步，可展开看 8 站） | 信息架构最完整，但需设计展开交互 |
| **并列展示**（现状） | 用户同时看到两套，无法判断自己在哪 |

### 决策点 3：ADR-0010 的 8 站是否仍然有效

| 选项 | 代价 |
|---|---|
| **仍然有效** | 后端不用改（已严格实现）。#5 需要接上或明确删除 |
| **作废** | 需写 ADR supersede ADR-0010，后端 `progress.py` 8 站定义要跟着改，会触发 `make check-api-drift`（删路由改 openapi.json） |

**注意**：若决策点 1/2 的结论是"用户动作层与引擎阶段层是两个东西、都要保留"，
那么 ADR-0010 的 8 站很可能是**仍然有效**的——它描述的是引擎层，从未被 08-18 的课设定位否定过。
08-18 否定的是"期刊投稿器"这一定位（`devlog-2026-08-18.md:4`），不是引擎的 8 个阶段。

### 决策点 4：`spec.py:86` 的默认模板

`template: str = "cn_journal"`（期刊模板）与 08-18「本科课程论文工作台，不是期刊投稿器」冲突。

但 `devlog-2026-08-18.md` 无 ADR 地位，**严格说 `cn_journal` 从未被正式作废**。

| 选项 | 代价 |
|---|---|
| 确认作废，改默认值 | 改 1 行 + 相关测试 |
| 确认保留 | 08-18 的定位声明需要正式撤回，否则代码与文档长期冲突 |

## Non-Goals

- 不改引擎阶段本身（8 站的对错不在本文档讨论范围，那是 ADR-0010 的事）
- 不改 LangGraph 图结构

## 附：若选择「折叠引擎层，只呈现用户动作层」的连带项

- `PaperPath` 的 8 个英文标识符（`i18n.tsx:190-197`）需汉化或移出用户视野
- `paperPath.ts:95-96`：`translate_code` 与 `export_docx` 同源派生自 `canExport`，永远同步跳变——需补一个中间信号
- `JourneyTimeline` 死链（`progress.py:39-48` → `JourneyTimeline.tsx` → i18n 中英各 8 条 → 测试）需要决定接上还是整体删除
  - 删除会触发 `make check-api-drift`（`/journey` 路由消失 → openapi.json 变更 → `types/api.ts` 需重新生成）
