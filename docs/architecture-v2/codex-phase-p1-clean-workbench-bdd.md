# P1-R Clean Research Workbench BDD

目标：把 P1-Q 的“档案型界面”继续收敛成更干净的大型研究工作台。当前页面仍有纸格背景、重阴影、过大的标题和嵌套卡片，数据页还出现变量确认步骤卡片与数据路径重叠。P1-R 先修信息密度和布局卫生，再考虑更强的视觉个性。

## 参考原则

- JupyterLab：主工作区负责当前对象，侧栏/属性检查器只放上下文和工具，不抢主内容。
- Grafana：复杂信息用轻量 panel、顶部上下文控制和可复用变量，不把每个对象都做成巨大卡片。
- OpenMetadata：数据资产需要 glossary、lineage、quality 等语义关系，前端应先展示关系和证据，不先暴露工程目录。

## 行为 1：全局背景必须干净，不能使用纸格噪音和装饰性阴影

**Given** 用户打开任意一级页面  
**When** 页面加载完成  
**Then** 主背景应为低噪声底色，不能使用明显 grid-paper 背景  
**And** panel shadow 必须非常轻，不能靠大阴影制造层级

业务规则：当前用户反馈“脏”，第一步要降低视觉噪音，而不是继续加强装饰。

## 行为 2：数据与变量页的变量确认入口不能发生重叠

**Given** 数据页存在 `analysis_sample.csv`  
**When** 渲染变量角色确认入口  
**Then** 数据集摘要、步骤说明和主操作必须垂直排列或在安全宽度内分栏  
**And** 长路径必须可换行，不能压到右侧步骤卡片下面

业务规则：变量角色确认是 P1 主链路入口，不能让用户在第一步看到重叠和遮挡。

## 行为 3：右侧档案索引必须更像属性检查器

**Given** 用户在任意阶段页  
**When** 查看右侧栏  
**Then** 右侧栏应以当前对象、相邻页面、证据图例为主  
**And** 样式应更紧凑、更轻，不再像一堆小卡片

业务规则：右侧栏承担 JupyterLab-style inspector 角色，不是第二个内容流。

## 行为 4：页面组件必须减少嵌套卡片

**Given** 用户查看数据、执行、结果或导出页面  
**When** 页面中出现 panel 内的子对象  
**Then** 子对象应使用列表、条目、表格或轻量 record，不应继续使用大卡片套大卡片

业务规则：大型系统要靠信息分组和可扫读结构提高效率，不靠重复卡片制造层级。

## 行为 5：保留现有技术栈和 API

**Given** 本轮是视觉/交互清洁迭代  
**When** 修改代码  
**Then** 不引入新前端框架、不改 API、不改 P1 后端状态机

业务规则：这轮只修用户可见体验和布局卫生，不能扩大到架构迁移。

## 边界

- 不实现真正 graph backlinks。
- 不实现新的 docx 导出审批。
- 不重写所有旧版页面。
- 不复制任何参考产品的品牌、插图或完整页面结构。
