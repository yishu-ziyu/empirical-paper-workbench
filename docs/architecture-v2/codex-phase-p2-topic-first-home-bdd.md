# P2-Q Topic-first Home BDD

本阶段修正首页信息架构：用户进入产品后，应先选择或输入一个研究选题，再进入变量、设计、执行计划、SupervisorPlan 等判断环节。首页不应默认铺开所有工程模块。

## 行为 1：首屏必须是研究选题入口

Given 用户打开工作台首页  
When 项目数据加载完成  
Then 首屏主区域必须显示“开始一项实证研究”，并提供输入研究问题的区域。

业务规则：用户先表达研究目标，系统再展开后续判断；不能一进来就把所有功能模块铺满。

## 行为 2：用户可以从已有选题继续

Given 项目已经有 `research_question` 或项目标题  
When 首页渲染选题入口  
Then 页面必须显示“从已有选题继续”，并把当前项目问题作为可确认的候选。

业务规则：已有项目不能丢失上下文，但也不能直接跳进复杂工作台。

## 行为 3：用户可以从真实数据候选池开始

Given 用户暂时没有明确选题但有真实数据资产  
When 首页渲染选题入口  
Then 页面必须提供“从真实数据候选池开始”的入口，并路由到数据与设计工作区。

业务规则：实证论文可以从数据反推问题，但这个动作仍然是入口选择，而不是直接进入 run log。

## 行为 4：研究判断区默认隐藏

Given 用户尚未确认选题  
When 首页完成渲染  
Then 下一步研究决策、主链路、智能中控、SupervisorPlan、风险、建议和事件流必须放在一个隐藏或折叠的研究判断区中。

业务规则：降低短时记忆负担，避免首屏信息量冲爆用户。

## 行为 5：确认选题后展开研究判断区

Given 用户输入或选择一个研究选题  
When 用户点击“进入研究判断”  
Then 页面保存本次前端选题状态，并展开研究判断区，显示下一步研究决策和证据审阅入口。

业务规则：本阶段只建立前端入口状态，不直接改写后端 VariableRoleSet、DesignSpec 或 RunPlan。

## 边界条件

- 本阶段不新增后端 topic API；选题确认先保存在前端状态和 `localStorage`。
- 选题确认只影响首页显示，不直接改写研究状态机。
- 数据候选池入口只切换到“数据与设计”页，不自动绑定数据。
- 后续 P2-R 再把确认后的 topic 变成可审计的项目级 ResearchQuestion 状态对象。
