# 产品控制文档包

这个目录不是工程架构文档，而是产品经理视角的控制台。它回答三个问题：

1. 这个产品为什么存在。
2. 第一版到底要让用户完成什么。
3. 后续每个功能如何验证它真的有用。

如果后续开发任务无法挂回这里的用户场景、产品原则或 MVP 验收标准，就先不要做。

## 和工程文档的关系

- `docs/current-product-map.md` 记录当前系统已经长出来的产品骨架。
- `docs/architecture-v2/` 记录架构、BDD、API 和阶段契约。
- `docs/product-control/` 记录产品判断、取舍、作品集叙事和验收方式。

工程文档解决“怎么实现”，本目录解决“为什么这样做、做到哪里算有用”。
