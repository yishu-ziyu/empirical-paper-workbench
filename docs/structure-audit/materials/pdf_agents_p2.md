## 1. Harness（本段核心）

### 1.1 公式回扣（与 Ch1 对齐）

```text
模型决策（调什么工具、传什么参数）
        ↓
Harness / Agent 框架执行（真 API、真代码）
        ↓
结果写回 messages 轨迹 → 再请求模型
```

- API 调用 **无状态**：每次必须送完整历史；“记忆”在 harness 维护的 `messages` 列表里。
- Harness 核心工作 = **管理 messages 列表**：何时追加 assistant / tool / meta，再整包送给模型。
- 本章所有上下文工程 = 优化这个列表的内容与结构。

### 1.2 上下文骨架（每次调用）

```text
┌─ 静态前缀（勿动 → 利于 KV / Prompt Cache）─┐
│  System Prompt  +  Tool Definitions           │
└───────────────────────────────────────────────┘
┌─ 动态轨迹（可增长 / 可压缩）─────────────────┐
│  user → assistant → tool → user → …           │
│  + Skills 按需加载内容                        │
│  + Status Bar（末尾 meta user 消息）          │
└───────────────────────────────────────────────┘
```

**铁律三条（生产默认，非研究前沿）：**

1. 系统提示词与工具定义一旦定下 **不要改**（多一空格也整段 cache 失效）。
2. 动态信息 **永远追加末尾**（时间戳、状态、用户配置），不要塞进 system 前缀。
3. 用 **标准 API 角色**（system/user/assistant/tool），勿自拼 `"USER:… ASSISTANT:…"`——伤的是指令遵循与 CoT 连贯，不只是缓存。

### 1.3 KV Cache / Prompt Cache 作为架构约束

| 层级 | 作用 | 设计含义 |
|------|------|----------|
| KV Cache | 单次推理内复用历史 K/V | 前缀字节稳定 |
| Prompt Cache | 跨请求复用前缀（API 计费） | Anthropic 常需 `cache_control`；OpenAI 自动前缀缓存 |

**生产级后果（Claude Code 类实践）：**

- 提示词结构由 **缓存边界** 切分：边界前 = 全局可共享缓存；边界后 = 用户/会话动态。
- 子 Agent 提示词 / 工具 / 模型配置 / 消息前缀须与父 **字节级对齐**，才能蹭父请求的 Prompt Cache。
- 大工具输出被摘要替换时，**替换字符串首次冻结**，会话恢复也复用同一串，避免 cache 失效。
- **缓存经济性是前置约束，不是事后优化。**

**有害模式（实验 2-3）：** 动态 system 时间戳、动态用户配置嵌前缀、工具定义动态重排、滑动窗口丢历史、纯文本拼消息。

### 1.4 Agent Status Bar（状态栏 = Harness 仪器）

**问题：** 上下文学习更像 **检索** 而非一次前向里的 **归纳**；“打了几次电话”散落在轨迹里，模型常数错、循环重试。

**机制：** Harness 在轨迹 **末尾** 注入结构化元信息（API 上常借 `role: user` + `<agent_status>` / `<system-reminder>`），紧邻生成位置，强制注意力。

**内容类型：**

| 类型 | 例子 | 缓存友好性 |
|------|------|------------|
| 任务规划 / TODO | pending / in_progress / done | 动态更新 |
| 侧信道 | 时间戳、地理、距上次回复间隔 | 追加即可 |
| 环境状态 | cwd、OS、工具重复调用 N 次 | 动态 |
| 可用能力清单 | Skills 元数据目录 | 变化少；emit-once |

**更新两策略：**

1. **每轮替换** 旧状态消息：上下文干净；从移除点起局部 cache 失效（比改 system 便宜）。
2. **持久追加**（Claude Code system-reminder）：只 append，cache 全友好；旧状态累积，靠模型看“最新一条”。

经验：长轨迹 + 高频更新 → 倾向持久追加；短轨迹或单条状态巨大 → 可替换。

**五件套技术（实验 2-8）：** 时间戳前缀 · 工具调用计数 · TODO 工具 · 详细错误四层 · 系统状态感知（含 cd 后更新 cwd）。组合产生涌现式自适应行为。

**Context Distillation 证据（书内研究）：**

- 弱模型准确率可 +40–54pp；强模型主要省思考 token / 延迟 / 费用（约一个数量级）。
- 有状态栏后，思考量对上下文长度 **近似恒定**（“瞥一眼”）。
- **状态栏用代码维护，别用 LLM 批量扫历史统计**（正则 20 行 > 前沿模型 bulk summary）。
- 删原文前确认状态栏覆盖会被问到的全部维度；假权威状态栏可把准确率打崩。
- **模型几乎无条件信任状态栏** → 准确率当一线生产指标；禁止可被外部污染的数据源写入（投毒面）。

**时间感三轴（状态栏 + 操作手册）：**

| 轴 | 含义 | 读数来源 |
|----|------|----------|
| 紧迫度 urgency | 力气匹配时钟预算 | 时间戳 |
| 坚持度 persistence | 真墙 vs 假墙、是否做完 | 工具计数 |
| 警觉度 vigilance | 慢调用 / 空成功当假设 | 时延 vs expected |

**关键发现：** 只塞原始读数几乎无效；**读数 + 策略手册** 才能改行为（+19–+49pp）。简单“到 3/3 就停”可只靠读数；节奏类决策必须成对给策略。

**与 Loop 工程：** 状态栏 = “交互缩放”第三条轴的日常落地——Harness 观测真实世界（退出码、重试次数、测试是否过），写回模型想不出来的新信息。验证器若假，循环空转。

### 1.5 Skills 在 Harness 中的位置

渐进式披露三层：

1. **元数据**（启动常驻 ~数百 token）：`name` + `description`；description 写成 **Use when / Don't use when + 反例**（路由条件 > 功能介绍）。
2. **SKILL.md 核心流程**（按需 ~2K）：作为 tool result / meta 进入轨迹。
3. **子文档 / scripts / 模板**（再按需）。

**注入方式三：**

| 方式 | 优点 | 缺点 |
|------|------|------|
| 改 system | 指令遵循最强 | 每次加载破前缀 cache |
| 当普通文件读到中间 | 不破 cache | 中部指令遵循依赖模型训练 |
| **生产：元数据动态可见 + 专用 Skill 工具按需加载** | cache + 开销 + 遵循兼顾 | harness 实现细节（role 包装可演变） |

**emit-once：** skill_listing / skill_content 只付一次 cache_creation，之后 HIT；消息索引不挪动，只 append 末尾。

原则：交互模式对齐 **模型厂商训练约定**（Claude ↔ Skills/结构化提示）。

### 1.6 分层压缩（生产 Harness 五层，约 Claude Code 参照）

1. 工具结果预算：大输出落盘，模型只看冻结摘要预览  
2. 噪声直接删除（不对噪声做摘要）  
3. API 层微压缩（服务端从前缀移除指定 tool result；适合即将溢出）  
4. 归档式摘要（类 git log 逐轮保留脉络，非 squash）  
5. 全量 LLM 压缩 + **连续失败熔断器**（防压缩死循环烧钱）

优先前三层；后两层兜底。

**压缩 vs 隔离：** 子 Agent 在独立上下文做大搜索/读盘，只回传几百 token 结论 → **隔离优于压缩**；主前缀与 KV 不受中间噪声污染。任务描述必须自包含。

### 1.7 回扣 Ch1 五个上下文组成部分

- Skills 内容进入 **工具执行结果**  
- 压缩 = 对轨迹消息的精炼替换  
- Status Bar API 上是 user 槽，语义上是 **环境/进度元信息**（五件套的补充注解，非新类别）

## 2. Tools

### 2.1 API 循环（最小实现）

```text
while True:
  response = chat(messages, tools)
  append assistant
  if no tool_calls: break
  for each tool_call:
    result = execute_tool(...)   # harness 执行
    append role=tool, tool_call_id, content
# 生产必须 max_iterations 熔断
```

- 模型可 **并行** 多个无依赖 tool_calls；harness 可并行执行。  
- 第二次请求必须原样带回上次 assistant.tool_calls + tool 结果（`tool_call_id` 关联）。

### 2.2 工具定义设计（静态前缀质量）

好工具描述应含：使用边界（NEVER …）、具体示例、性能提示（Batch tool calls）、工具协作关系（编辑前至少 Read 一次）。细节书指 Ch4。

**工具渐进披露（2026+ API 原生）：**

- OpenAI Responses：`tool_search` + `defer_loading: true`  
- Anthropic：Tool Search / `tool_reference`；Claude Code MCP 默认延迟加载  
- Codex CLI：`tool_search`（BM25）默认开  

共同点：前缀只留名称+简述；完整 schema **首次发现时 append 到轨迹末尾**，之后固定位置、不每轮重搬 → 不破既有 K/V。修改/重排已加载工具集会从变动点失效。需模型训练支持“对话中部出现工具定义”（较新模型）。

### 2.3 Skills 与工具关系

- 全量专用工具堆进 system → token 膨胀 + 变更破 cache。  
- **Skill + 少量通用执行器**（书后文约七核工具）→ 专用逻辑按需披露。  
- Skill 可捆绑可执行脚本/模板（知识 → 能力）。

### 2.4 工具结果作为状态提炼点

在 tool result 中直接写“本次是第 3 次呼叫（3/3）”比让模型扫全文数数可靠。状态栏是该思想的全局化。

### 2.5 详细错误回灌

错误四层：类型描述 · 完整参数 JSON · 调用栈 · 针对性修复建议 → 错误场景替代方案成功率书内示例 60% → 95%。

## 3. Eval（本段出现的评测/消融）

本段 **不是** 独立 Eval 章，但给出可复用的 **Harness 可测性** 方法：

| 实验 | 测什么 | 关键数字/结论 |
|------|--------|----------------|
| 2-2 注意力可视化 | Attention sink、位置偏好、CoT 三角 | Lost in the Middle；关键信息放头/尾 |
| 2-3 错误上下文模式 | 动态 system、滑窗、文本化 | 滑窗 → 丢 tool 结果 → 循环重调 |
| 2-4 提示消融（Tau-Bench 航司/零售） | 语气 / 组织 / 工具描述 | 打乱组织成功率 **>30%↓**；去工具描述错误率 **+45%** |
| 2-5 提示注入攻防 | 直接/间接/记忆注入 | 对照：基线 / 警告 / XML 来源标记 / 组合 |
| 2-6 Skills 论文→PPT | 渐进加载端到端 | 元数据→SKILL.md→子文档→脚本 |
| 2-7 状态栏注意力 | 有/无状态栏约束遵守 | 小模型无栏易违约束；有栏锁注意 |
| 2-7 扩展 Context Distillation | 计数/规则/状态跟踪 ×11 模型 | 弱模 +40–54pp；强模省 ~1 数量级 |
| 2-8 状态栏五技术 | TODO 等 | 有 TODO ~15 iter vs 无 21 + 漏子任务 |
| 2-9 压缩策略对比（128K 预算） | 6 策略 token/轮次/成败 | 见下表 |

**压缩策略对比（实验 2-9，OpenAI 联合创始人追踪任务）：**

| 策略 | Token（约） | 压缩率* | 迭代 | 结果 |
|------|-------------|---------|------|------|
| 无压缩 | 166K | 102% | 5 | 失败（溢出） |
| 个体摘要 | 277K | 10.9% | 12 | 成功 |
| 组合摘要 | 93K | 4.3% | 10 | 成功 |
| **上下文感知** | **40K** | **3.0%** | **7** | **成功（优）** |
| 感知+引用 | 223K | 4.1% | 10 | 成功 |
| 自适应窗口（80% 阈值批量压） | 175K | 102% | 7 | 成功 |

\*压缩率 = 压缩后/原文；越小压得越狠。上下文感知：压缩提示带 `query` + 已有 context；示例 147877 字符 → 1963 字符仍保关键事实。

**Eval 方法论 implicit 原则：**

- 消融优于凭感觉重写提示。  
- 评的是 **Model + Harness 配置**，不是裸模型。  
- 状态栏 / 压缩 / 组织方式均应用任务成功率 + token + 迭代次数量化。  
- 验证器必须扎根真实观测（否则 Loop 空转）——与产品 claim audit / REPRO 同构。

## 4. Memory（本段：会话内 vs 跨会话开篇）

### 4.1 会话内“记忆”= 轨迹 + 提炼

| 机制 | 角色 | 持久性 |
|------|------|--------|
| messages 全量历史 | 原始事件日志 | 会话内；API 无状态 |
| Status Bar / 工具侧计数 | 显式状态（代码维护） | 会话内；可导出 |
| 上下文压缩摘要 | 高密度知识表示 | 会话内；可审查/可设计跨会话复用 |
| 滑动窗口 | **反模式** | 丢 tool 结果 → 重复调用 |

CoT / reasoning_content 策略（行业转向）：

- 旧 R1：多轮剥离历史思考（省 token；Agent 易丢“为何调工具”状态）  
- DeepSeek V4 / Kimi K2 / GLM-5：强制回传 reasoning_content  
- Claude：tool 循环内 thinking block 原样回传（带签名）；新用户轮后服务端可忽略历史 thinking  
→ **对 Agent：思考是状态，不是废料。**

### 4.2 压缩即记忆整理（会话尺度）

双动机：

1. 长度/成本约束  
2. **思考质量**：总结后的知识比原始散落结果更利于检索式使用  

原则：

- 信息价值非均匀（决策点 > 证据 > 噪声）  
- 语义完整（时间、主体不可丢）  
- 任务相关（同文不同任务 → 不同压缩）  
- 压缩即理解（可审查、可复用）  

**生产保留优先级（压缩时）：**

1. 架构决策与关键约束 — 不得摘要  
2. 已改文件列表与关键变更 — 完整保留  
3. 验证状态 pass/fail — 必须保留  
4. 未解决 TODO / 回滚笔记 — 必须保留  
5. 工具输出 — 可删，留结论  

标识符（UUID、hash、IP、端口、URL、文件名、PR/commit）**原样保留**。

**上下文腐化（Context Rot）≠ 溢出：** 装得下但找不到；信息密度错、稳定规则与动态状态混装。Karpathy：有限窗口逼迫抽象是 feature。

### 4.3 第 3 章开篇：用户记忆 vs 知识库（p80）

```text
用户记忆（个体）              知识库（群体）
  偏好/习惯/需求模型            法规/流程/专业文档
  Mem0 / Memobase 等           分块 · 稠密/稀疏 · 混合检索
  情景/语义/程序 认知类型       RAPTOR · GraphRAG · 智能体化 RAG
         ↘ 共享底层：检索 ↙
  双层记忆架构：Advanced JSON Cards 常驻概览
              + 上下文感知检索按需取细节
```

- 用户记忆 = **主动持续学习**，额外 LLM 算力抽取/压缩对话 → 可审查的用户预测模型。  
- 对比上下文学习：后者临时、会话结束消失。  
- 与 Ch2 同一哲学：**显式提炼，不靠模型被动捞针。**

（详细机制在 p3 批次；本文件仅边界。）

## 5. 安全（与 harness/tools/memory 交叉）

**提示注入：** 外部内容（网页/邮件/PDF/EXIF）伪装指令劫持有工具的 Agent → 不可逆动作。

上下文层防御：

1. 来源标记 `<external_content source="…">`  
2. 严格 Chat Template 角色（tool 结果勿混 user）  
3. 输入清洗（弱，仅辅助）  

新注入面：

- **第三方 Skills** = 高权限“外部当指令” → 安装前当代码审查  
- **状态栏** 被高度信任 → 禁止污染源写入  
- 记忆注入（实验 2-5 场景三）：会话植入 → 写入记忆 → 跨会话影响  

执行层（权限/沙盒/高风险确认）与检索投毒 → 后文/Ch3。分层防御，上下文层不能单独保证安全。

## 6. 对实证论文工作台的直接映射

| 书机制 | 产品落地建议 |
|--------|--------------|
| messages = 轨迹 SSOT | run 目录不可变 trace；每轮 append |
| 静态前缀稳定 | 系统规则 + 工具 schema 固定；主题/数据动态末尾或 tool |
| Status Bar 代码维护 | 工具调用次数、估计是否收敛、REPRO hash、TODO 步骤用代码写，不用 LLM 扫 log 统计 |
| 读数 + 策略手册 | gate 红灯时注入“已失败 N 次 / 允许回炉步骤 / 停止条件” |
| Skills 渐进披露 | 识别/估计/写作/复现 skill 元数据常驻，正文按需 |
| 工具 ACI | 结构化 ok/error + 参数回显 + 修复建议 |
| 压缩保留优先级 | 规格决策、claim、表 hash、pass/fail、未解决 TODO 不可摘要掉 |
| 隔离 > 压缩 | 大检索/全库扫交给子 agent，主环只收回摘要 |
| 验证器真实观测 | quality / claim audit / REPRO 必须读真实产物，禁自评过门 |
| 熔断 | max_iter、压缩失败熔断、同工具 N 次上限 |
| Eval 消融 | 改 harness 配置用任务成功率 + token + 轮次验收，非感觉 |
