# P1 Archive Interface BDD

目标：把现有产品页面从普通 SaaS 控制台，收束成有个人研究档案气质的可浏览界面。参考方向是知识花园、双链笔记、个人产品证明、履历式项目证据和收藏架，但不复制任何原始品牌、插画、文案或页面结构。

## 行为 1：全局框架必须呈现研究档案身份，而不是营销首页

**Given** 用户打开本地产品页  
**When** 首屏渲染  
**Then** 页面必须显示“研究档案”“本地证据”“相邻笔记”等档案语义  
**And** 不应出现大 hero、营销口号或装饰性渐变球。

业务规则：这个产品是个人研究工作台，不是 SaaS landing page。视觉入口要帮助用户理解“这是一份可追溯研究档案”。

## 行为 2：所有一级页面必须有持久的相邻笔记 / 反向链接索引

**Given** 用户在任意一级页面  
**When** 查看右侧区域  
**Then** 用户应看到当前页面附近的研究对象、证据等级图例和可跳转的相邻页面入口。

业务规则：借鉴双链笔记和知识花园，页面之间不是孤立标签页，而是一组可探索的研究材料。

## 行为 3：证据与产物必须以档案条目陈列

**Given** 页面展示数据、执行、结果或导出相关对象  
**When** 用户扫读卡片或列表  
**Then** 视觉结构应偏向 ledger / shelf / note item，而不是大号空卡片堆叠。

业务规则：每个视觉元素都要承担信息作用：路径、证据等级、状态、下一步动作，而不是只做装饰。

## 行为 4：核心组件必须有 hover、focus、loading、empty、error 状态

**Given** 用户用鼠标或键盘浏览页面  
**When** 聚焦导航、按钮、档案链接或遇到加载/空/错误状态  
**Then** 页面必须有明确的可见反馈，且状态样式不能只依赖颜色。

业务规则：这个界面要能长时间使用，状态反馈必须稳定、可扫读、可键盘操作。

## 行为 5：视觉修改必须保留现有技术栈和数据结构

**Given** 当前前端是 vanilla JS + CSS + 静态 HTML  
**When** 做档案型界面升级  
**Then** 不引入新前端框架，不改变已有 API 数据结构，只在显示层重组信息。

业务规则：本阶段目标是可验证的小范围升级，不把 P1 状态机和后端契约打散。

## 边界说明

- 保留机器契约字段：`run_id`、`evidence_level`、`local_file`、`local_execution`、文件路径和 API 路径。
- 不新增外部图片依赖；Maggie Appleton 方向只吸收“纸张、注释、解释性结构”的气质。
- 右侧档案索引先做静态 + 当前页面高亮，不在本阶段实现真正双向图谱数据库。
