## 1. 第 7 章：模型后训练（能力写入参数）

### 1.1 三阶段与两条主线

现代模型能力分三阶段炼成：

1. **预训练**：NTP，语言与世界知识地基（极贵）。  
2. **SFT**：输入–输出示范，固化格式/风格/流程协议（便宜、稳）。  
3. **RL**：任务 + 奖励，无唯一标准答案，最大化期望回报（贵、不稳、上限高）。

贯穿主线：

| 主线 | 内容 | 论文台默认落地 |
|------|------|----------------|
| SFT 记忆 / RL 泛化 | SFT 逼近唯一示范；RL 强化任意高奖励策略，OOD 更稳 | 规格/表格 schema 用示范与校验；设计漂移靠 **重规划与再估计**，不靠“背住一份 design” |
| 数据与环境 > 算法 | 先验基模 > 仿真保真 > 数据质量 > 算法微调 | 复现沙箱、数据门、claim 证据链优先于“换 RL 算法”幻想 |

**先形后神**：先 SFT 把输出可解析（JSON/表/do-file 契约），再谈策略优化。格式乱时奖励不可计算。强基模可跳 SFT 直接 RL（如 R1-Zero），但生产仍常回冷启动 SFT 立形。

### 1.2 何时后训练 vs 只做 Harness

书决策序：

1. Harness（prompt / 工具 / 上下文）能解 → **不训练**。  
2. 需训练 → **先 SFT**（格式、协议、风格）。  
3. 部署分布系统性漂移、示范非最优、标注极贵 → **再 RL**。

**对本仓库**：课程论文级工作台默认停在 (1)。后训练仅在未来垂直小模型（如固定期刊体例、稳定 Stata 方言）才值得；事实（系数、文献）必须走 **证据库 / RAG / 运行日志**，禁止后训练“背事实”。

### 1.3 奖励与信用：给 evaluate / learn 用的词汇

| 概念 | 书意 | 实证环映射 |
|------|------|------------|
| 二元 / 结果奖励 | 成功=1 失败=0 | REPRO 绿/红；关键回归是否复现 |
| 过程奖励 / PRM | 逐步反馈 | 设计→数据门→估计 分阶段门禁；勿把过程 KPI 当最终真理 |
| 向量 / 生成式奖励 | 多维或自然语言诊断 | paper_quality + claim audit + 引用：结构化诊断，非单一总分 |
| RLVP：奖结果、罚路径 | 违规动作可机器判定则扣分 | 禁止无证据 claim、改测试式“假绿”、跳过 integrity |
| 信用分配 | 长轨迹归因难 | 失败要落到 **target_steps**（哪几步重跑），不能只标“论文质量差” |
| 环境反馈 loss mask | 环境 token 不回传策略梯度 | 工具/Stata 输出是证据，不是“要背下来的答案” |

评估环境可改造成训练/学习环境，但 **训练用任务集与黄金评测集必须隔离**（书举 SWE-bench 例）。论文台同理：demo 种子题不可泄漏进 held-out 验收。

### 1.4 实践陷阱 → 产品红线

1. 用后训练记事实 → 用 evidence / replication。  
2. 格式未稳就“优化策略” → schema 与 adapter 先绿。  
3. 奖励黑客 → 评最终可复现与 claim 真值，不评“字数/像论文”。  
4. 仿真失真 → 真跑 Stata/复现脚本，不靠模型口述“已复现”。  
5. 过度优化当前题 → held-out 与规则变更阶段（见 ch8 实验 8-6 精神）。

### 1.5 本章对 audit 的可验收命题

- [ ] 门禁输出是 **多维诊断 + 证据指针**，不是模糊总分。  
- [ ] 有 **结果层**（复现/表数字）与 **过程层**（规则、claim 证据）分离。  
- [ ] 无“只要 SFT 数据就行”式的假装调参路线绑架主路径。

## 2. 第 8 章：持续进化（H8 / L8 核心）

### 2.1 能力悖论与工程路径

Agent 可零样本解新题，却可能在同类任务一万次后仍犯第一天错误。  
推理后参数不自动变；**上下文内适应 ≠ 跨任务学会**；**落盘日志 ≠ 学习**。

学习 = 系统主动完成 **评价 → 对照 → 归纳 → 验证** 之后，才改后续行为。  
生产反馈脏、有注入与遗忘风险 → **禁止未经验证的在线改参**。  
现阶段路径：在模型外围建可验证学习系统（轨迹 → 候选 → 回归 → 发布）。

### 2.2 三层轨迹验证（评价先于总结）

```text
  质量层  LLM Rubric（表达、论证合适性）—— 仅难形式化部分
  过程层  规则/权限/动作序列/承诺–行动一致
  结果层  环境真值（测试、库状态、工具返回）—— 优先代码
```

客服例可换成论文维度（建议作为 learn 信号 schema）：

| 维度 | 验证问题 | 证据 |
|------|----------|------|
| 任务结果 | 设计是否可估、表是否出、稿是否齐 | 产物路径、run 状态 |
| 规则遵从 | 是否跳过数据门/完整性审计 | 门禁日志 |
| 事实可靠性 | 系数/引用是否有证据 | evidence 图、表 JSON |
| 承诺–行动一致 | “已复现”是否真有 repro 绿 | replication 日志 |
| 降级诚实 | 证据不足是否降级而非硬编 | claim 状态 PASS/降级 |
| 表达质量 | 章节结构、可读性 | Rubric + 人可打开的 md |

**验证器给诊断，改什么由独立诊断/进化模块决定**；避免同一模型既当裁判又直接改规则。

### 2.3 四种更新载体（能力写在哪）

| 方式 | 适合 | 优势 | 局限 | 论文台默认 |
|------|------|------|------|------------|
| 经验知识库 | 条件–策略、例外、来源 | 快、可追溯 | 靠检索与正确应用 | 跨题教训、数据坑、规格陷阱 |
| Prompt / Skill | 可语言化规范 | 可解释、可控 | 膨胀、冲突、被忽略 | 章节 skill、integrity 规则最小 diff |
| 程序 / Harness | 确定性流程与硬约束 | 可测、稳、便宜 | 开发成本 | **主战场**：门禁、adapter、repro、step 图 |
| 模型参数 | 风格、隐式策略、感知 | 泛化、推理省 token | 回归贵 | 远期；非当前主路径 |

选择原则：根因定位后取 **最小、最易验证、可回滚** 的载体。偶发故障先攒样本。

正式知识单元要求：适用场景、推荐策略、禁止做法、例外、证据来源、最近验证时间。  
**跨轨迹支持门槛**（书：≥2 条非失败轨迹）后再升级正式文档；原始轨迹不可变，分析与正式知识分库。

### 2.4 优化尺度（内容 vs 方法）

由内向外（优先内侧）：

单条规则/记忆 → 结构化上下文 → 工作流 → Harness 代码 → 优化器本身  

局部补丁默认；跨组件长期无解再升层。  
**评价器、权限、留出测试必须在可修改范围之外**（可信根）。

### 2.5 双循环（产品结构原型）

```text
  在线执行环：  跑 10 步 / 估计 / 成文 / 复现 → 只追加不可变证据
                      │
                      ▼  版本化经验库 + 评估集
  离线进化环：  聚合 → 诊断根因 → 候选修改 → 门槛验证 → 灰度/回滚
```

Voyager 三件套类比论文：

| Voyager | 论文台 |
|---------|--------|
| 自动课程 | 下一轮改哪几步 / 哪条假设 |
| 技能库 | 通过验证的 skill / do-file 片段 / 设计模板 |
| 环境验证 | Stata 复现、表哈希、claim 审计 |

### 2.6 发布门槛与分层评估

所有修改先 **候选**，不直接盖生产：

- 知识：held-out 任务是否更好  
- Prompt/Skill：边界集升、保留集不退化  
- 程序：沙盒 + 失败重放 + 回归  
- 参数：遗忘与安全  

拆开评：

| 指标 | 问题 |
|------|------|
| 候选修改有效率 | 更新器是否提出有用补丁 |
| 产物激活率 | 任务 Agent 是否加载新 skill/记忆 |
| 遵循成功率 | 加载后是否真执行 |
| 留出任务增益 | 未参与进化的题是否变好 |

长期同时盯：回退、泛化、Token、安全、**工程质量**（可维护、所有权、兼容）。

### 2.7 开放任务边界（论文尤其相关）

自动科研压力测试（书引 Trehan & Chopra 等）：

1. **实现漂移**：难了就退回训练分布里的烂实现。  
2. **认识论乐观**：噪声当发现；阴性结果被抹掉。  
3. **隐性判断不足**：不知何时弃假设、哪条基线重要。

对策映射：

| 书 | 论文台 |
|----|--------|
| 结论与证据分离（Chain-of-Evidence） | evidence spine；稿只是证据图的一种呈现 |
| 保留负面结果 | 失败规格、不显著、被拒候选进不可变日志 |
| 搜索多样性 | 勿把 learn 收敛成“同一易得分模板” |
| 人在高层 | 丢料、验收、抢方向盘；不逐步签到 |

### 2.8 安全三界 + 睡眠学习

1. **证据与指令隔离**：网页/工具输出经总结与审阅再入库。  
2. **候选与正式隔离**：新 skill/门禁阈值先 canary。  
3. **安全机制不可自改**：验证器、审计日志、发布门槛、稳定备份 **禁止** 业务 Agent 修改。

睡眠学习五步：触发 → 定向 → 采集整合 → 验证审批 → 修剪索引。  
容量：合并重复、全局 prompt 减负、过期能力归档、必要时从基座重训 LoRA。

### 2.9 与 L8 的硬映射（structure-audit 用）

| 书机制 | 仓库应有（目标） | 缺则状态 |
|--------|------------------|----------|
| 在线只记证据 | 不可变 run workspace + 轨迹 | PARTIAL 多形态 |
| 离线才进化 | evaluate 后独立 learn 模块 | L8 常 MISSING |
| 候选→验证→发布 | release_to_canary / reject | 红灯仍 completed 则失败 |
| 结构化诊断驱动重跑 | quality 红 → target_steps | 仅红灯清单不算环 |
| 跨轨迹门槛 | 偶发失败不立刻改正式 skill | 需策略 |
| 可信根外置 | integrity / repro 门槛不可自改 | 硬约束 |

**L8 假实现识别**：线性 10 步跑完 + 红灯 JSON + 人工看清单 = **地图有、环没有**。  
真 L8：`evaluate 失败 → 诊断归属步骤 → 生成候选（改 design/spec/code）→ 验证 → 同图重入 → max_rounds 或 package`。

## 3. 第 9 章：多模态与实时（边缘映射）

### 3.1 边界

静态图/PDF 理解已是工具调用，不必专章架构。  
本章难在 **实时流 + 严格时延**：语音、Computer Use、机器人。  
**多模态生成**（生图）只是工具，不在实时主线。

### 3.2 对论文台仍有用的三块

**A. 快慢解耦（思考架构方案二）**  
前台维持交互 / 进度；后台强模型做设计推敲、文献综合、长稿修订。  
接口优先 **纯文本契约/状态栏**（“正在估 IV；repro 未绿禁止宣称完成”）。  
Computer Use 书结论：抽掉快慢文本通道，成功率可塌到 0。

**B. 观察与动作解耦（AOI）**  
把“看见了什么”写成可持久文字，再决策。  
映射：表截图/回归图 → 叙述进 trace，不依赖上下文里永远留着原图。

**C. 过早完成禁令**  
状态摘要未确认完成前，快路径 **不许** 说办好了。  
映射：`repro`/`claim` 未绿前，成文与 package 不得写“已复现/稳健”。

### 3.3 刻意不做

- 语音全双工主路径  
- GUI 代操 Stata 作为默认（优先 do-file / MCP 确定性接口）  
- 机器人  

审计时 ch9 最多给 **H1 工具完备** 与 **停止条件** 加分，不支撑 H8 主结论。

## 4. 第 10 章：多 Agent 协作（H7 核心）

### 4.1 两个正交维度

```text
              共享上下文                    不共享上下文
           （同轨迹换角色）              （独立轨迹 + 显式 IO）
  拓扑
  对等      阶段内自审较弱              提议者–审核者 + 外部反馈
  管理者    少见                        Manager + 专长子 Agent
  去中心    transfer 链式               handoff 包 + 消息池
```

| 依据 | 共享 | 不共享 |
|------|------|--------|
| 子任务数 | 2–3 | 多、需并行 |
| 窗口 | 装得下 | 单窗装不下 |
| 并行 | 串行接力 | 真并行 |
| 隔离 | 弱 | 强（审计/安全） |
| 成本 | 轨迹累积 | 总 token 常高数倍 |

经验：累计上下文将超窗口 ~50% → 不共享 + 提炼 handoff。  
信息零损耗是硬约束 → 共享（如紧密的 design↔data 澄清）。

### 4.2 何时多 Agent 真的更好

**唯一硬判据：协作是否引入生成时不存在的新信息？**

| 模式 | 新信息？ | 效果 |
|------|----------|------|
| 同模型自审同一文本 | 否 | 常无效甚至有害 |
| 纯辩论同一文本 | 否 | 等算力下≈单 Agent |
| Reviewer 跑测试/复现 | 是 | 显著 |
| Reviewer 看渲染/图表 | 是 | 显著 |
| 外部工具核事实 | 是 | 显著 |

→ **H7 验收**：必须有独立 workspace/进程或至少独立工具结果 IO；  
仅换 system prompt 的“审稿人角色” = persona 剧场，不算达标。

成本：多 Agent 可到普通对话约 15× token；收益必须盖过成本。

### 4.3 三种拓扑 → 论文角色

**对等 / 提议者–审核者**（Loop 工程默认心智）

- 过早终止三类：偷懒假完成、过早放弃、假成功。  
- 解法同一：由 **验证器** 裁定停止，不是模型自称。  
- 论文：Writer 出稿/表注；Reviewer **只信** integrity + repro + 证据图，不信“我觉得系数合理”。

**管理者 / 编排**

- Manager 当工具调用其他 Agent；子 Agent **返回结构化摘要 + 路径**，不全量轨迹。  
- **弱规划者是系统瓶颈** → 最强模型与最好 prompt 给规划/路由，不是均分。  
- 论文：Orchestrator 拆 10 步、派 literature / estimate / write / repro；上下文只留索引与状态机。

**去中心 handoff**

- 移交包三件：任务描述与验收、已确认事实与约束、产物路径。  
- 不传全量试错轨迹。  
- MetaGPT 式 SOP：角色输出结构化交付物；消息池订阅解耦。  
- 防环：handoff 次数上限。

### 4.4 基础设施（OS 类比）

| OS | Agent |
|----|--------|
| 程序 | 静态前缀（prompt + tools） |
| 进程内存 | 轨迹 |
| CPU | LLM |
| fork/kill/ps | spawn / cancel / list |
| 退出码 | 结构化摘要 |
| 共享内存 / 消息 | 共享目录 / 总线 |

虚拟目录四区：

1. Agent 私有 scratch  
2. 任务共享 workspace（用户可见、需并发控制）  
3. 外部挂载（只读为主）  
4. 系统 skills（只读、渐进披露）  

控制面：消息信封、进度文件或轨迹 JSONL、优雅/强制终止、token/步数预算与抢占。

### 4.5 失败模式（必防）

**MAST 三大类**：系统设计缺陷、Agent 间对齐失败、任务验证缺失。  
Agent 故障偏 **拜占庭**（继续一本正经地错），靠冗余与确定性外部反馈断链。

| 失败 | 论文场景 | 缓解 |
|------|----------|------|
| 文件丢失更新 | 并行改正文与表 | worktree / 乐观锁 / 单写者 |
| 跨文件语义冲突 | 改编号不同步引用 | 编排层禁并行依赖写；全局一致性检查 |
| 错误级联放大 | 错译术语 → 全书“一致”更可信 | 交叉验证；Reviewer 只看原始证据 |
| 循环失控 | 无限 revise | max_rounds、预算、人 prioritizes 验收 |
| 理解债 / 认知投降 | 自动稿无人读 | package 必须人可打开验收 |

### 4.6 预算感知

单纯加步数不提升性能；需按剩余预算调探索/利用。  
Manager 应对简单步少预算、因果/成文多预算，并强制“规划–实现–测试–改”节奏。

### 4.7 Agent 社会（刻意降权）

小镇涌现、市场机制雇佣等为前沿。  
课程论文工作台 **不** 以开放社会为架构目标；保持目标明确的任务协作 + 验证闭环即可。

## 5. 合成映射：设计→估计→成文→复现→修订

### 5.1 产品环 × 书机制

```text
  用户丢料
      │
      ▼
  ┌────────── 在线执行（ch8 上环 / ch10 编排）──────────┐
  │  01 设计     契约与风险（形）                         │
  │  02 文献     检索工具 = 新信息                        │
  │  03–05 数据/设定/估计   真跑代码 = 结果层证据         │
  │  06 成文     提议者；claim 必须链证据                 │
  │  07–08 审与完整  审核者 + integrity（新信息）          │
  │  09 复现     确定性 ORM/结果奖励                      │
  │  10 交付准备  仅当门禁允许                            │
  └────────────────────┬─────────────────────────────────┘
                       │ evaluate（三层验证）
                       ▼
            绿 ──► package（可打开论文 + 复现包）
            红 ──► learn（ch8）
                       │
                       ├─ 根因 → 载体（知识/Skill/程序）
                       ├─ 候选 + 变更契约（预期修/预期伤）
                       ├─ 回归 + 可信根
                       └─ 重入 target_steps 或升层改 Harness
                       │
                  max_rounds / 人验收
```

### 5.2 10 步角色建议（避免剧场）

| 步 | 建议形态 | 必须的新信息/验证 |
|----|----------|-------------------|
| 01 设计 | 强规划单 Agent 或共享上下文澄清 | 因果问题可测、风险显式 |
| 02 文献 | 工具检索 Agent | 真实检索结果，非编造引用 |
| 03–04 数据 | 代码/适配器 | schema、覆盖、门禁日志 |
| 05 估计 | 执行 Agent + 结果落盘 | 表 JSON/日志哈希 |
| 06 成文 | Proposer | 每个 claim → evidence id |
| 07–08 审 | Reviewer **独立** IO | integrity、引用核验、测试 |
| 09 复现 | 确定性脚本优先于 LLM | 独立环境跑通 |
| 修订 | learn 模块非“再生成一遍” | 诊断→最小补丁→重跑 |
| package | 环终点同图 | 人可 open 的稿 + repro |

### 5.3 H1–H8 / L 关键项对照（材料摘要）

| ID | 书出处 | 实证台读法 |
|----|--------|------------|
| H1 | 全书 Harness；ch7 参数互补 | 模块可消融：工具/记忆/门禁/编排 |
| H2 | ReAct + 停止；ch10 验证器停 | max_iter + 门禁硬停，非假完成 |
| H3 | ch8/10 渐进 skill、索引 | 不整库倾倒 |
| H4 | 工具完整返回 | Stata/读表结构化 ok/error |
| H5 | 轨迹=状态；ch8 不可变证据 | 可回放 run |
| H6 | ch7–8 评测先于进化 | 黄金集与训练/学习隔离 |
| H7 | ch10 新信息 + 独立 IO | spawn/workspace/工具结果 |
| H8 | ch8 双环四载体 | propose→verify→ship |
| L8 | ch8 离线进化 + ch10 Loop | evaluate→learn→重入 |

### 5.4 反模式清单（审计用 falsifier）

1. 线性 pipeline `completed` 且 quality 红仍当成功。  
2. “审稿 Agent”与写稿共享脑内独白、无外部检查。  
3. learn = 追加一段 prompt，无回归、无候选版本。  
4. 业务 Agent 可改自己的 integrity 阈值或删失败用例。  
5. 多编排栈主权撕裂（无单一 PaperLoop SSOT）。  
6. 用满意度式“像论文”标量替代复现与 claim 证据。  
7. 阴性结果与失败设计不入日志，只留幸存故事。  
8. 无限 revise 无 max_rounds / 无预算。

### 5.5 近期实现优先级（书推工程序）

1. **单一环编排 SSOT**：在线 10 步 + evaluate + learn 重入 + package 同图。  
2. **评价器外置且不可自改**：结果层（repro/表）+ 过程层（claim/规则）+ 质量层。  
3. **失败 → target_steps**：信用分配到可重跑步骤。  
4. **候选产物目录**：skill/prompt/代码 diff + manifest；过线才 canary。  
5. **真 Reviewer IO**：独立调用 integrity / repro，不靠自言自语。  
6. 经验库跨 run 提炼（有支持门槛）——在 1–5 稳后再做。  
7. 后训练 / 语音 / GUI——明确非当前成功标准。

## 6. 术语速查（中英）

| 术语 | 含义 |
|------|------|
| 先形后神 | SFT 立格式，再 RL/策略优化 |
| RLVR / RLVP | 可验证结果奖励 / 再加路径惩罚 |
| ORM / PRM | 结果奖励模型 / 过程奖励模型 |
| 在线执行 vs 离线进化 | 跑任务只记证据 vs 聚合后改候选 |
| harness-updating vs harness-benefit | 会改 Harness vs 会用上改动 |
| 移交包 handoff | 任务+事实约束+路径，不含全轨迹 |
| 新信息判据 | 多 Agent 是否引入外部反馈 |
| Loop 工程 | 循环+验证器裁定停止 |
| 可信根 | 验证器/门槛/审计不可被业务自改 |
| 候选 / 正式 | canary 前隔离 |

## 7. 材料结论（供 critic 打）

1. **Continuous Empirical Loop 的书侧主支撑是第 8 章双环 + 第 10 章“验证器驱动的 Loop”，不是第 7 章调参，也不是第 9 章语音。**  
2. **H7 的否证很硬**：无外部新信息的多角色 = 无效；有 repro/integrity 独立 IO 才算。  
3. **H8/L8 的否证很硬**：无候选–验证–重入，仅有红灯清单 = 未进化。  
4. **第 7 章贡献的是评价与信号哲学**（多维诊断、奖结果约束过程、数据环境优先），应写进门禁与 learn 信号，而非立刻 SFT 论文模型。  
5. **开放科研失败模式**（实现漂移、假发现、丢阴性）与本产品“降级诚实 + 自动改设计重跑”同构；证据图与不可变失败日志是一等公民。
