# Main Workbench Clean UI BDD

## 背景

用户在首页研究工作台看到大量状态文字、告警和旧阶段面板平铺，反馈界面“很乱、很脏”。本轮只清理主工作台的信息架构和视觉层级，不改变后端工作流语义。

## 行为用例

### BDD 1：固定演示题目读取真实项目

Given 用户打开题目“父母的教育水平如何影响子女的工资水平？”
When 首页生成 Product Control 项目编号
Then 页面必须映射到 `proj_empirical_paper_template_main`
And 不能使用临时 `proj_topic_*` 项目导致状态“未读取”。

业务规则：固定 demo 线已经有真实项目和 P17 数据修复状态，首页必须直接读这条线，不能让用户看到空壳项目。

### BDD 2：连接诊断默认折叠

Given 用户进入首页工作台
When 服务状态栏存在预检或连接诊断
Then 诊断内容必须折叠在“连接状态”下面
And 第一屏不能铺开大段技术告警。

业务规则：连接信息是辅助排错，不是研究推进主任务。

### BDD 3：当前卡点优先

Given Product Control 已经推进到 P17 数据修复预检
When 首页渲染 Product Control
Then P17 当前卡点必须出现在 P11/P9 旧门禁之前
And P11/P9 作为次级工作区折叠展示。

业务规则：用户第一眼只需要知道当前真正卡在哪里，旧阶段只能作为复查入口。

### BDD 4：研究流程降级为折叠摘要

Given Product Control 是当前主操作区
When 首页渲染阶段导航、当前动作、阶段门槛
Then 这些流程说明必须收进“研究流程”折叠区
And 不再与当前卡点争夺第一屏。

业务规则：阶段路线是上下文，不是此刻的主操作。

### BDD 5：桌面和移动端不横向溢出

Given 用户在桌面或手机宽度打开首页
When 页面渲染长中文题目、状态和表单
Then 主工作台不能产生横向滚动
And 文本必须在容器内换行。

业务规则：页面必须看起来像一个可用产品，而不是调试面板堆叠。

### BDD 6：研究简报区域跟随浅色工作台

Given Product Control 下方还有研究简报操作区
When 用户滚动到简报启动卡片
Then 该区域必须使用同一套浅色产品界面
And 不能继续显示旧的深色大面板。

业务规则：主工作台必须整体一致，不能上半屏清爽、下半屏仍像调试面板。

### BDD 7：默认层只讲用户能理解的下一步

Given 用户进入首页工作台
When Product Control 渲染当前进度
Then 默认可见区域必须展示“现在要做什么”和“下一步”
And 使用“父母教育信息”“工作经验”等中文业务词
And 不把 P 编号、source contract、RunPlan、字段英文名作为主要内容。

业务规则：用户不是来读内部流水线状态的；首页必须回答“我现在该做什么”。

### BDD 8：技术细节默认关闭

Given 页面仍需要保留工程复查信息
When 用户没有主动展开技术详情
Then P9/P11/P17、source metadata、RunPlan 等细节必须收在“技术详情”折叠区内
And 旧门禁复查区不能默认展开。

业务规则：工程细节可以保留，但不能默认占据主屏。

### BDD 9：后端服务页面时使用同源 API

Given 用户从 FastAPI 后端地址直接打开首页
When 页面读取固定 demo 的 Product Control 状态
Then 前端必须默认请求同源 API
And 不能因为本地旧端口配置回退到空壳状态。

业务规则：用户直接打开可用页面时必须看到真实研究进度，而不是连接到错误端口后的空状态。
