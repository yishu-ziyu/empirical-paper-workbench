# 创作台：写小论文的工作区（方案）

状态：2026-09-24 提出，**方案，尚未实施**。交互原型在 `frontend/prototypes/paper-workspace.html`（开发服务器下打开，第 1 个变体「创作台」）。

## 一句话

左边是研究列表，中间是和研究助手的对话，右边是一份排印好的稿子。助手改稿时，用户能看到一个带名字的光标飞到那里，先选中，再重写。改动先问后做，做完可以一键撤销。

## 为什么这样定

写小论文的人真正在做的事，是在“想清楚”“算出来”“写下来”三件事之间来回切换。目前的痛点有三个：

1. 在 Stata、Word 和聊天窗口之间来回搬东西；
2. 改了设定之后，正文里的数字悄悄过时；
3. AI 改了哪里看不见，只能整篇重读。

对应的四条设计原则：

| 原则 | 做法 | 参照 |
|---|---|---|
| 稿子是主角，对话是手柄 | 对话线程在中间；稿子作为工件占最大面积，用论文排印而不是网页排版 | Claude / Kimi 客户端的工件面板、Claude Science |
| 过程看得见 | 助手的每次改动都有光标轨迹：到哪、选中什么、写了什么；计算显示为可展开的工具卡 | Google Docs 协作者光标、Claude Science 的可复现工件 |
| 信任靠可撤销，不靠关卡 | 影响多处的改动先问一句；每组改动一键撤销；稿子有版本号 | Cursor 的改动审阅、版本历史 |
| 代码完整披露 | 稿子里每个数字都能追到实际运行的代码；代码随稿子交付，可复制、可下载、可在本机重跑 | 期刊复现包（AEA Data Editor 的要求）、Claude Science 工件自带代码 |

正文里的数字不是写死的文字，而是指向证据的引用（Ref）：点一下就能看到来源，设定一变就能自动标出哪些已经过时。

## 已定的决策（2026-09-24）

| 问题 | 决定 | 谁定的 |
|---|---|---|
| 一项研究能开几条对话 | 多条。共用同一份稿子、数据和计算记录 | 用户 |
| 第一版能不能直接在稿子里打字 | 能，但只限段落文字；表、图、公式和正文数字不能手改 | 用户委托，理由见 [界面层](ui.md#作者直接编辑) |
| Notebook 做什么 | 只做计算记录，不让用户写代码；但代码必须完整披露给用户 | 用户 |

## 分层方案

- [界面层与交互](ui.md)：三栏布局、光标的行为、对话里的卡片类型、页边批注
- [数据层](data.md)：稿子块、数字引用、改动集、审稿批注，以及它们和现有证据、运行对象的关系

## 原型里的约定

原型用写好的脚本模拟研究助手。只有 OLS 与 IV 两组数字来自真实运行（`docs/design/first-value-entry/card-pair.json`）。光标、打字和撤销的节奏是真实组件实现的，可以直接看手感。
