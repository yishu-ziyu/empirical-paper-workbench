# P3 React Research Input And Slide Tabs BDD

本阶段只做用户指定的两个 UI 基础组件：研究输入器和阶段滑动导航。目标是先确立新前端的产品气质与交互手感，不继续在旧 vanilla 页面上堆模块。

## 行为 1：研究输入器以题目输入为首要动作

Given 用户打开新的 React 研究工作台  
When 页面完成渲染  
Then 首屏必须显示一个居中的研究输入器，用户可以输入研究题目或任务说明，并在非空时提交。

业务规则：产品入口先让用户表达研究目标，而不是一开始铺开全部执行、证据、Agent 和日志。

## 行为 2：文件和长文本作为附件预览，而不是冲进主屏

Given 用户拖拽、选择文件或粘贴长文本  
When 研究输入器接收这些材料  
Then 页面必须把它们渲染为可移除的预览卡片，并显示类型、大小或文本片段。

业务规则：大块材料应该先被折叠成输入附件，避免首屏信息过载；后续分析由 Agent 读取附件，不在 UI 中直接铺满。

## 行为 3：模型或工作模式选择在输入器内部完成

Given 用户需要选择本地 Codex、自动研究或半自动审阅模式  
When 用户打开输入器底部的模式选择器  
Then 页面必须显示可选择的模式列表，并把当前选择保留在输入器状态中。

业务规则：中控模型和工作流模式是任务启动参数，不应该分散在多个页面角落。

## 行为 4：阶段滑动导航只暴露当前研究路径

Given 用户进入新的 React 工作台  
When 阶段导航渲染  
Then 页面必须显示任务书、递归搜索、数据变量、方法设计、执行实验五个阶段，并支持点击或键盘聚焦切换。

业务规则：导航服务于研究生命周期，不再按技术目录或旧模块名组织第一屏。

## 行为 5：视觉系统限定为黑白灰

Given 用户明确要求第一版只使用黑白灰  
When 研究输入器、附件卡片、模式选择器和阶段导航渲染  
Then 组件的主色、边框、状态和焦点样式必须只使用黑、白、灰色阶，不引入绿色、紫色、蓝色或渐变球。

业务规则：第一版先建立干净、克制、未来感的产品基调；状态差异通过明度、边框、透明度和动效表达。

## 行为 6：新前端独立构建，不覆盖旧页面

Given 旧版 `Product/web` 仍然是当前可用产品面  
When 本阶段新增 React/Vite 前端  
Then 源码必须放在 `Product/web-react`，构建产物输出到 `Product/web-dist`，并通过 `/react` 预览，不删除旧 `Product/web`。

业务规则：新设计满意前保留旧入口作为回退；等用户验收通过后再删除旧前端。

## 边界条件

- 本阶段不实现完整 Agent Task Queue、右侧审计 Drawer 或全模块迁移。
- 输入器提交只形成前端状态和预览结果，不静默覆盖正式研究状态。
- 文件预览只读取浏览器可访问的本地上传文件；线上版本仍需要后端上传与云端处理链路。
- 黑白灰约束适用于本阶段新增 React UI；旧 vanilla 页面不在本阶段统一重绘。
