# 00 产品愿景

## 一句话定位

本地 AI 实证研究 OS：把实证论文从“题目、数据、文献、方法、回归、写作、复现”这些分散步骤，组织成一个可审计、可人工确认、可持续迭代的论文初稿生产流水线。

## 它解决的核心问题

做实证论文的人经常不是卡在某一个工具上，而是卡在整个链路里：

- 有题目，但不知道需要什么数据和变量。
- 有数据，但不知道变量角色是否合理。
- 有模型，但不知道识别策略是否站得住。
- 有回归结果，但不知道能不能写进论文。
- 有 AI 生成文本，但不知道哪些内容有证据，哪些只是像论文的语言。
- 有很多中间文件，但复盘时不知道每一步是谁做的、为什么做、产物在哪里。

这个产品的任务是把这些混乱步骤变成一个可见的研究工作台。

## 产品信念

AI 不应该偷偷替研究者做决定。AI 应该把复杂研究拆开，把证据、风险、下一步动作和人工确认点暴露出来，让研究者重新拥有判断权。

这个产品追求的是“一键生成可审计的论文初稿”，不是一键生成看起来像论文的无证据文本。它必须同时做到：

- 让研究路径可见。
- 让证据链可追。
- 让 Agent 分工可审计。
- 让草稿和正式稿分层。
- 让用户知道下一步该做什么。

因此第一版用户体验必须以 `paper_draft.pdf / paper_draft.docx` 为中心。审计报告、问题清单和运行日志是支撑文件，不是用户第一眼要理解的主产物。

## 为什么先做本地版

第一版用户是项目作者本人和少数熟人。本地版更适合快速验证：

- 能直接读取本机数据。
- 能使用本地 Codex、Python、StatsPAI、StataMCP 等工具。
- 能把运行日志、产物和论文草稿直接落在 Git 仓库。
- 能快速看出流程哪里断了，而不是先被云端权限、上传、队列和计费复杂度拖住。

云端产品仍然必须做，但它应该复用同一套状态机、证据模型和 Agent 编排。云端只是把本地路径换成上传对象，把本地执行换成云端沙盒。

## 作品集意义

这个项目不是只展示“我会写代码”。它要展示产品经理能力：

- 识别复杂用户问题。
- 定义产品边界。
- 设计核心用户旅程。
- 把 AI 能力转成可验证工作流。
- 在功能、可信度、用户体验之间做取舍。
- 用真实 demo 和运行证据证明产品推进过。
