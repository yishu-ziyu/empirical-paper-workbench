# 现有产品和论文（2026-08-13）

给产品判断用。还不是产品说明书。

## 判断

可以做。
产品是整条实证研究链：搜文献、读文献、综述、提出假设、找数据、分析、写成论文。
不是只做估计和写稿。文献工具和 Agent 流程论文里写的那些，都是产品里的一段，不是别人的事。

要注意一件事：如果「探索」交出来的是另一篇读起来很正规的论文，别人会把它当正式结果用。
所以探索这边应先交出所有试过的设定和结果。若再写一篇稿，要写明这是搜过设定之后写的。

## 别人在做什么

Discovery Loop：自动跑科学和工程实验。先从机器学习做起。不写经济学论文。

Sakana 的 AI Scientist：自己想题目、写代码、跑实验、写成机器学习论文。能出稿，可信度差。

CoPaper.AI 和 StatsPAI、AERS：同一作者。数据到实证草稿。你已经在用它的计量库。再做一遍同样的东西没有意义。

OpenEcon 的 econ-auto-research：强调识别是否站得住、事先定分析、自己审自己、数字能追溯。工具已经有一些，全流程还在路线图上。这是最像的经济学方向，而且偏「事先说好再跑」。

Causal-Copilot：对表格做因果发现和推断，出分析报告。不是经济学论文，也不管识别策略。

Elicit、SciSpace、PaperQA2：搜文献、读论文、写综述、问答。产品里要有这一段，不是别人的事。

Korinek 2025、Dawid 等人 2025：经济学家用 Agent 做研究的流程。产品要按这个做出来，不是只当参考文献。

历史上的旧 CLI 模板已经能从题目和数据走到稿，红了会改后半段；
它还不能「设计谈完人就走」，也几乎不会系统地把很多设定跑一遍。

econpaper：唯一产品，当前做网页端。识别、文献、设定表、逐章写都在这一条路上。
2026-09-01 完成能力核对后，旧 CLI 模板从本地工作区删除，不再是开发入口。

## 论文里和这件事有关的

Gelman 和 Loken（2013）写过：不一定是存心造假，分析过程里合理的分叉本身就会造出显著结果。

Simonsohn、Simmons、Nelson 的设定曲线：把所有说得通的设定都跑一遍，看结论是不是只在少数设定里成立。

Steegen 等人（2016）的多元宇宙分析：同一问题的多种合理数据处理，全部报告。

Leamer（1983）和 Brodeur 等人的工作：经济学里搜设定、堆显著结果，是老问题。

事先写分析计划的传统：先定设计，再看结果。

这些材料支持「可以搜很多设定」，但搜完应把全部结果摊开，而不是只留下好看的那一篇。

## 和我们前面聊的对上之后

仍然成立的部分：

- 交出来的是论文，外加试过的设定表。
- 先把设计谈完，再离开去跑。
- 人负责谈、同意开跑、回来看、中途要停就停。
- 一个能看数据、查文献、检查识别的 Agent。

按你这次补上的：

- 搜论文、读文献、写综述、提出假设，都在产品里。
- 找数据、分析、写稿，也在产品里。
- 模板里这几步名字都有。文献现在主要是核验一串已知 DOI，不是真的检索和精读。数据现在是磁盘上已有的表，不是去找、去下。假设还没有单独做成一场能谈完的对话。

## 产品本身

整条链都做：搜文献、读、综述、假设、找/拿数据、谈设计、估计、写稿、复现。

公开能下的自己下。CFPS、CHARLS 写出申请入口，文件放进来之后继续。
父母教育工资是一条现成的题，用来跑，不是产品的边界。
换题目就是换研究方向，还是同一个网页产品。
