# 05 MVP 验收标准

## MVP 定义

作品集 MVP 不是完整 CoPaper，也不是完整云端 SaaS。

第一版 MVP 是：

> 用户输入一个研究题目，系统在本地生成一份可审阅的论文初稿包。正向分支输出完整 `paper_draft.pdf / .docx`；阻断分支输出半成品论文、红标缺口和问题清单。

`paper_draft.pdf / .docx` 是第一版最重要的用户体验交付物。任务书、数据与变量候选、方法设计、执行计划、证据风险和审计报告都服务于这个交付物。

## 必须完成的用户闭环

### 闭环 1：题目进入系统

输入：

- 一个中文实证研究题目。
- 可选数据路径。
- 可选方法偏好。

验收：

- 系统生成当前题目的 `ResearchIntent`。
- 页面和 CLI 都不显示旧题污染。
- 产物里能看到当前题目。

### 闭环 2：任务书可确认

验收：

- 用户能看到研究问题、研究边界、数据线索、方法倾向和成功标准。
- 用户能确认、修改或重跑。
- 未确认任务书前，不直接进入正式回归结论。

### 闭环 3：Agent Queue 可理解

验收：

- 用户能看到每个 Agent 的任务。
- 每个任务有输入、输出、状态和产物路径。
- 需要人工确认的地方有明确提示。

### 闭环 4：数据与变量有证据等级

验收：

- 数据候选显示来源、路径、行列数、字段画像。
- 变量角色候选显示原因和证据等级。
- 启发式推荐不能伪装成正式变量角色。

### 闭环 5：方法设计能解释

验收：

- 系统能说明为什么推荐某个方法。
- 系统能列出前置条件。
- 条件不足时能明确阻断或提示补证据。

### 闭环 6：执行结果可追溯

验收：

- 执行产物包含日志、表格、图或失败原因。
- 每个结果能追到 run id、脚本、数据和参数。
- 没有真实执行结果时，不生成主结果结论。

### 闭环 7：论文初稿可交付且不越权

验收：

- 系统必须输出 `paper_draft.pdf` 或 `paper_draft.docx`，至少有一个用户可打开的论文初稿文件。
- 新题目不会自动并入旧论文正文。
- 初稿必须声明当前证据状态。
- 证据不足时输出半成品论文和红标问题清单，而不是伪装成完整论文。
- 论文式结论必须有 evidence_id。

### 闭环 8：审阅和导出给出明确状态

验收：

- 导出失败时说明缺什么。
- formal writeback 需要人工确认。
- 用户能看到“现在可以导出 / 还不能导出 / 需要修什么”。

## 展示级验收

作品集展示必须准备：

1. 一个 3 分钟 demo。
2. 一个固定案例。
3. 一张产品流程图。
4. 一张 Agent 分工图。
5. 一张证据链截图。
6. 一份 `paper_draft.pdf / .docx` 初稿样例。
7. 一份产品案例页。
8. 一份“下一步路线图”。

## 当前项目到 MVP 的缺口

当前最主要缺口：

- 前端/CLI/文档之间的叙事还没有统一。
- LLM Supervisor 的真实介入需要更稳定地展示。
- Evidence Registry 对论文正文的硬门禁还需要继续收束。
- 真实数据到真实论文包的闭环还需要选一个固定案例做到底。
- 作品集案例页尚未完成。

## MVP 通过标准

当以下问题都能回答时，MVP 才算过：

- 用户是谁？
- 他为什么痛苦？
- 产品怎么帮他？
- 第一版不做什么？
- Demo 怎么跑？
- 结果在哪里？
- 哪些结论有证据？
- 哪些地方需要人工确认？
- 面试官 3 分钟能否理解这个产品？
