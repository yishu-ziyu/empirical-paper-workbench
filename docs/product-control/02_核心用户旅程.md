# 02 核心用户旅程

## 总旅程

```text
输入题目
-> 确认研究边界
-> 发现数据和变量
-> 生成变量角色候选
-> 生成研究设计
-> 生成 RunPlan
-> 执行实验
-> 绑定结果证据
-> 生成 paper_draft.pdf / .docx
-> 审阅与导出预检
```

## 阶段 1：输入题目

用户来到产品时，第一屏只做一件事：输入研究题目、数据线索或方法偏好。

用户看到：

- 一个干净的输入框。
- 当前模式：本地 Codex Supervisor / 人工审阅模式 / Auto Mode。
- 可附加材料：数据路径、文献片段、方法要求。

系统输出：

- `ResearchIntent`
- 当前题目摘要
- 初步任务编号

验收标准：

- 用户知道自己现在要输入什么。
- 页面不铺开完整 Agent 队列、日志、方法树和审计细节。

## 阶段 2：确认研究边界

系统把题目拆成任务书，不直接跑回归。

用户看到：

- 研究问题。
- 研究对象。
- 数据线索。
- 方法倾向。
- 成功标准。
- 不确定点。

系统输出：

- `TaskBrief`
- `EvidenceRequirement`
- `RiskList`
- `NextAction`

验收标准：

- 用户能确认“这是不是我想研究的问题”。
- 如果题目太宽，系统应要求收窄，而不是继续生成正文。

## 阶段 3：Agent 任务队列

Supervisor 把任务拆给不同 Agent。

用户看到：

- DataAgent 做什么。
- LiteratureAgent 做什么。
- DesignAgent 做什么。
- ExecutionAgent 做什么。
- ManuscriptAgent 做什么。
- Verifier 做什么。

默认只展示任务摘要。点击后才展开日志、证据、成本、skill 和工具调用。

系统输出：

- `SupervisorPlan`
- `AgentTaskQueue`
- `SkillSelection`

验收标准：

- 用户知道“谁在干什么”。
- 用户知道哪一步需要人工确认。
- 每个 Agent 任务都有产物路径。

## 阶段 4：数据与变量

系统从本地数据或用户指定路径中找候选数据，并生成变量画像。

用户看到：

- 数据源候选。
- 文件大小、行数、列数。
- 字段画像。
- 缺失值和异常提示。
- 变量角色候选。

系统输出：

- `DatasetProfile`
- `VariableProfile`
- `VariableRoleCandidate`

验收标准：

- 用户能判断这个数据是否适合当前题目。
- 变量角色必须标明证据等级，不能把启发式推荐当成最终结论。

## 阶段 5：研究设计

系统根据题目、数据、变量和方法库生成设计方案。

用户看到：

- 候选方法。
- 前置条件。
- 识别假设。
- 风险。
- 需要补充的证据。

系统输出：

- `DesignSpec`
- `MethodGate`
- `RunPlanDraft`

验收标准：

- 用户知道为什么推荐这个方法。
- 如果 DID、IV、RDD 等方法条件不足，系统必须明确阻断或提示补证据。

## 阶段 6：执行实验

系统按 RunPlan 调用 Python、StatsPAI、StataMCP 或本地脚本。

用户看到：

- 运行状态。
- 脚本。
- 参数。
- 表格。
- 图。
- 日志。
- 失败原因。

系统输出：

- `MethodExecutionResult`
- `RunManifest`
- `RegressionTable`
- `FigureArtifact`

验收标准：

- 每个结果都能追到代码、数据和运行日志。
- 没有真实执行结果时，不允许生成主结果结论。

## 阶段 7：结果与草稿

系统把真实结果转成 Finding，再生成用户可打开的论文初稿。这里的主产物不是后台报告，而是 `paper_draft.pdf / paper_draft.docx`。

用户看到：

- 论文初稿文件。
- 完整初稿或半成品状态。
- 关键发现和证据绑定。
- 红标段落或缺口占位。
- 问题清单入口。

系统输出：

- `FindingCandidate`
- `ResearchReport`
- `DraftPackage`
- `paper_draft.pdf`
- `paper_draft.docx`
- `audit_report.md`
- `issue_list.md`

验收标准：

- 草稿必须区分有证据内容和待补证据内容。
- 结论不能和表格、样本量、系数方向冲突。
- 成功分支输出完整论文初稿；阻断分支输出半成品论文和问题清单，不能只给用户一个诊断报告。

## 阶段 8：审阅与导出

系统做最终检查，不直接把草稿变正式稿。

用户看到：

- 占位符检查。
- 引用检查。
- 系数一致性检查。
- 样本量一致性检查。
- PDF/DOCX 预检。
- 复现包清单。

系统输出：

- `VerifierReport`
- `ExportPreflight`
- `FormalWritebackApproval`

验收标准：

- 只有人工确认后，才允许进入正式层。
- 导出失败要明确告诉用户缺什么，不要假装成功。
