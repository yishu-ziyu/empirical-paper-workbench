# Close read: Bellemare — How to Write Applied Papers in Economics (2020)

Local: `corpus/bellemare_how_to_write_applied.pdf`

## Core claims

1. Economists learn writing from polished “best of” papers + inspectional reading → hard to see what makes papers good.
2. Write sections in **research order**, present in **reader order** (intro/title/abstract late).
3. Best papers focus on **one narrow causal question** (or one clean mechanism question).
4. After Credibility Revolution, robustness is a full song-and-dance, not two extra tables.

## Structure to internalize

```text
Title, Abstract, Introduction
Theoretical framework
Data and descriptive statistics
Empirical framework
Results and discussion (core, robustness, heterogeneity, mechanisms, limitations)
Summary and concluding remarks
References, Appendix
```

Data ↔ Empirical Framework order can swap for clarity.

## Introduction = Head formula

Hook → Research question → Antecedents (5–10 closest, story form) → Value added → Roadmap.

Bad hook: “A long literature has studied…”  
Good hook: real-world stake the reader feels.

Busy readers: title → abstract → intro → **tables** → conclusion. Intro must minimize hunting.

## Data section checklist (product QA)

- Who collected, when, sampling rule, population represented  
- Target N vs actual N, nonresponse/attrition  
- Missing data rule  
- Every variable used defined; none unused  
- Descriptives: discuss outcome/treatment, not every control mean  
- Balance tables when treatment is categorical  
- Prefer present tense for scientific claims about the sample  

## Results discipline

- Most-to-least parsimonious control sets for observational work  
- Robustness: alternate Y, alternate D, placebos, falsification, alternate estimators  
- Heterogeneity after core+robustness  
- Mechanisms: mediation when possible; else admit untestable paths  
- Limitations: internal validity, external validity, proxy measures  
- Same sample across nested regressions  
- Table titles name estimator + causal relationship of interest + subsample  

## Conclusion

Summary (not clone of abstract) → limitations → policy implications only if supported → future research.

## Abstract

Plain English for smart non-economist; expand citation surface without sacrificing rigor.

## Title

Prefer “The effect of D on y: Evidence from [context]” over technique-forward titles.

## Direct product implications

1. Our writing agent must follow Head intro order, not “outline dump.”  
2. Quality gate section names already match Bellemare/AER skeleton.  
3. “Limitations” is not optional decoration — for OLS packages it is the load-bearing wall.  
4. Table self-containment is a first-class deliverable, not appendix fluff.  
5. One question: parent education ↔ child wage association under controls — do not smuggle five mechanisms without data.
