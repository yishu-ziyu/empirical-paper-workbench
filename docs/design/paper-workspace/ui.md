# 界面层与交互

> 上级：[创作台方案](README.md)

## 布局

| 区域 | 宽度 | 内容 |
|---|---|---|
| 研究列表 | 232px | 新研究；最近的研究，每项一行状态（“初稿 · 2 条意见”）。当前研究展开它的多条对话（如“改稿”“找数据”）和“新对话” |
| 对话线程 | 430px | 和研究助手的对话；工具卡、询问卡、改动卡；底部输入框和建议 |
| 工件面板 | 其余 | 标签页：稿子 / Notebook（后续加：数据）。稿子是一张排印纸，右侧页边放批注和来源纸条 |

窄屏（< 1100px）时对话与工件改为上下两个标签页，研究列表收成抽屉。原型只做了桌面宽度。

## 对话里的四种卡片

| 卡片 | 何时出现 | 用户能做什么 |
|---|---|---|
| 工具卡 | 助手读数据、跑模型、检查诊断 | 展开看代码；运行中显示转圈，完成后显示一行结果 |
| 询问卡 | 改动会波及多处，或需要用户做研究取舍 | 一次只问一个问题，给两个选项；选完留痕 |
| 改动卡 | 助手改完稿子 | 显示改了几处；“撤销”一键回到改之前 |
| 普通回复 | 其余情况 | 逐字流出 |

什么时候必须先问：一次改动碰到 2 处以上，或者会改变研究结论的措辞（例如把相关写成因果）。只改一处文字、而且可以撤销的，直接做。

## 助手光标

光标是助手在稿子上的“手”，让用户知道它在哪、在做什么。

1. 飞行：弹簧运动到目标（stiffness 170，damping 24），目标先滚进视野中部。
2. 点按：光标缩到 0.82，外圈放出一道波纹（160ms）。
3. 选中：目标文字加选区底色（逐行裁切，和真实文本选区一样），停 520ms。
4. 重写：清空后逐字打出，每 22ms 两个字，末尾有插入符。
5. 标签：光标旁的绿色标签写明动作，如“研究助手 · 改结果段”。

目标只用语义 id（`results`、`table-main`、`figure`、`intro-claim`），不用坐标或 CSS 选择器。这和现有的 `frontend/src/lib/agentCursor/registry.ts` 一致：组件注册自己，脚本只说 id。

减少动态效果（reduced motion）时：光标直接出现在终点，文字一次性替换，选区底色保留 150ms。

## 作者直接编辑

第一版支持，但只限段落文字。理由：

1. 论文是用户的。改一个词还要请助手，是在给写作添摩擦。
2. 架构上不多花钱：助手改稿本来就需要块版本、改动集和撤销，用户手改只是“作者是用户”的同一种改动集。先做它，可以在接入模型前把版本和撤销链路验证干净。
3. 数字不能手改。正文数字是引用，只能整体删除或移动；要改数字就改设定。否则“每个数字都能追到代码”这条承诺就破了。
4. 冲突规则：助手正在改的块对用户临时上锁（显示“研究助手正在改稿”）；用户正在编辑的块，助手的改动排队。

原型里点结果段或结论即可编辑，⌘↵ 保存，Esc 取消；保存后对话里出现一行“✎ 你改了结论 · 撤销”。

## Notebook：计算记录与代码披露

- 只读，按实际运行顺序列出每次计算；每个 cell 标明“用于：表 1 第 (1) 列、结果段”。
- 顶部写明数据文件、sha256 和运行环境。
- 可下载 `analysis.py`：就是实际运行的调用，注释里附本次结果。2026-09-24 用下载的脚本在本机重跑，OLS 0.0747（0.0035）、IV 0.1315（0.0550）、第一阶段 F 13.26 / 有效 F 14.14，与稿子一致。
- Stata、R 版是从 Python 翻译的，按钮上写明“翻译版，数值未核对”，核对通过后才去掉这行字。
- 失败或未采用的尝试也留在记录里，标明“未进稿”，不删除。

## 稿子

- 论文排印：宋体/Times 正文，节号，三线表，图题写成完整的句子。
- 数字是引用：点线下划线；点击后在页边出现来源纸条，纸条可以跳到 Notebook 里对应的 cell。
- 过时的数字标成暖黄色，直到有人接受更新或撤销改动。
- 审稿批注在页边，左边一道黄线；处理后变绿并变淡，不删除。

## 动效预算

高频操作（切标签、点按钮）不超过 200ms，只动 transform 和 opacity。助手改稿属于“演示过程”，允许更长（整组改动约 4–6 秒），但用户任何时候都能继续读、滚动、点击，不锁屏。
