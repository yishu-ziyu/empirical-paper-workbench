## 0. 总图：三章在 Harness 中的位置

```text
Ch4 工具/ACI ──► 让 Agent「能正确做事」的接口层
Ch5 可靠性/纠错 ──► 让 Agent「做错了还能回来」的约束·验证·纠正
Ch6 评估 ──► 让「有没有变好」可测、可归因、可回流
         │
         ▼

  Harness = 上下文 + 工具 + 约束 + 验证 + 纠正
```

审计含义：H4=ACI 工具；H1 的约束/验证/纠正与 Ch5 故障学强绑定；H6=评估对象是 **Model+Harness 组合体**，不是裸模型。

## 1. Tools ACI（Agent-Computer Interface）— 第四章核心 + 第五章七工具

### 1.1 必须存在的结构（must-exist）

| ID | 结构 | 定义/要点 | 缺了会怎样 |
|----|------|-----------|------------|
| T1 | **五类工具分工** | 感知 / 执行 / 协作 / 事件触发 / 用户沟通；前四类 Agent 主动调，事件触发=注册后外部唤醒 | 只会「用户说话才动」，无定时/外部事件/多渠道说话 |
| T2 | **能力表达二选一框架** | 专用代码工具 vs Skill+通用执行器；三维：参数复杂度、变更频率、模型能力 | 工具爆炸或 Skill 无法约束复杂传参 |
| T3 | **粒度整合规则** | 功能相似且场景重叠 → 合并（如 `read_document`+`file_type`）；参数集/频率差异大 → 保持独立 | >100 工具时选错率陡升 |
| T4 | **通用优先原则** | 通用工具优于专用，除非安全/权限/性能硬理由；`code_interpreter` 代替十几个计算器 | token 浪费、边缘场景全无覆盖 |
| T5 | **描述艺术（调用决策导向）** | 「何时用」>「能做什么」；边界/反例；参数带具体例子；返回值 schema；长耗时代价；**1–5 真实调用示例** | 选错工具却怪模型；改描述 ROI 通常 > 换模 |
| T6 | **参数保真性（无静默转换）** | 模型所见世界 ≡ 工具操作世界；禁止静默改输入/输出/注入参数；规范化须写进描述并回传告知 | 模型陷入不可自诊循环（弯引号、git 静默参数等） |
| T7 | **ACI 三代演进** | ①API 端点封装 ②目标导向 ACI（粒度/通用/描述）③调用示例 + 动态发现 + **代码编排**（中间态在执行环境，只回终结果） | 仍在「每步邮件汇报」式 token 烧法 |
| T8 | **MCP 三原语** | tools / resources / prompts；JSON Schema 描述；stdio 或 Streamable HTTP | 每框架重适配；资源与副作用动作混一谈 |
| T9 | **工具过多时的披露** | 默认索引（名/简述），按需加载完整 schema；Skills 渐进披露；代理工具「搜索→定义→调用」 | 5 个 MCP 即可 ~55k token 开销 |
| T10 | **主动工具发现** | 不全量注入；Agent 声明能力缺口或 `tool_search`；服务器级→工具级两层匹配；新 schema **追加轨迹末尾**保 KV Cache | 上千工具准确率崩（书：Opus 49%→74% 量级） |
| T11 | **感知工具接口** | 结构化候选+分页/cursor；read 的 offset/limit；**显式截断**（行数/如何续读）；超阈上下文感知压缩；只读可缓存可并行 | 静默截断 → 基于半截信息决策 |
| T12 | **执行工具安全栈** | 输入验证（快速失败、不智能修正）→ 权限/黑名单+语义解析 → 提议者-审核者 → Sidecar → 沙盒分级 | 单层字符串黑名单可被绕过 |
| T13 | **执行后自动验证闭环** | 写文件后 linter/语法检查结构化回传；可验证就自动验证 | 无「执行-验证-反馈」环，错误拖到多轮后 |
| T14 | **长输出截断+持久化** | 头尾保留 + 完整落盘 + 引导 read；中间省略可计数 | 上下文被刷爆或丢错误尾部 |
| T15 | **幂等与取消语义** | idempotency key / 先查后改；不可幂等 → 预检-确认两段式 | 超时重试双花（转账/发信） |
| T16 | **协作原语三组** | spawn / message / cancel + list_agents；HITL 超时降级 | 子任务泄漏 token 或无人兜底 |
| T17 | **事件结构化 + 三策略** | 来源/渠道/内容/上下文；取消式 / 队列式 / 并行式；轻量路由 LLM 判紧急度 | 紧急打断不了 / 常规查询打断主任务 |
| T18 | **同步模型的异步权宜** | 五规则：即时记 assistant；tool result 完成才记；打断用占位符；思考中打断丢弃思考；非紧急批量 | 轨迹格式非法或占位符幻觉 |
| T19 | **Coding 七核心工具**（Ch5） | Code Interpreter / Bash / Read / Write / Edit / Glob / Grep | 开放任务无元能力基座 |
| T20 | **MCP 信任边界** | 描述投毒、恶意服务器、同名遮蔽、凭证最小权限；description=不可信输入 | 工具定义本身即注入向量 |

### 1.2 ACI 核心原则（压缩）

1. **工具对 Agent 友好**（对标 HCI）：目标级操作，非 API 端点镜像。  
2. **描述服务决策**：边界反例 ≥ 能力列表；示例 > 抽象类型 alone。  
3. **保真**：无静默转换/注入；模型-工具世界零系统性偏差。  
4. **返回完整可行动信息**：错误结构化；截断可见；验证结果回传轨迹。  
5. **规模用披露解决**：Skills / tool_search / 延迟加载，非堆平铺 schema。  
6. **表达形态可迁移**：稳定底层→专用工具；高频变流程→Skill+执行器。

### 1.3 Falsifiers（ACI / 工具层）

| 声称 | 可证伪条件（观察到即失败） |
|------|---------------------------|
| 「工具描述合格」 | 固定任务下 Agent 反复选错工具；改描述后错误消失 → 根因是描述非模型 |
| 「参数保真」 | 读回内容与写入/匹配参数不一致且工具未声明转换 |
| 「截断安全」 | 返回未声明「省略 N 行/如何续读」，Agent 仍当全文 |
| 「按需发现」 | 会话启动即注入全部 MCP 完整 schema，token 与服务器数同步膨胀 |
| 「执行可验证」 | write 只回 success，从不回 linter/测试结构 |
| 「幂等安全」 | 同一写操作超时后盲目重试导致双写/双扣款 |
| 「Sidecar 隔离」 | Sidecar 读主模型自由文本思考，可被话术操纵放行 |
| 「通用七工具足够」 | 无文件/终端/解释器任一，却声称开放任务 Coding 内核 |

### 1.4 与实证论文 workbench 的映射提示

- 读数据/读 do/读论文片段 → 感知 + Read/Grep 族  
- 写 do/改表/跑 Stata → 执行 + 沙盒 + **写后自动校验**（日志/退出码/关键表存在）  
- 子任务并行调研 → 协作 spawn  
- 工具 registry 必须：schema + 边界 + 示例 + 结构化 error + 完整可观测返回

## 2. 可靠性 / 纠正（Reliability & Correction）— 第四、五章交织

### 2.1 必须存在的结构

| ID | 结构 | 定义/要点 | 缺了会怎样 |
|----|------|-----------|------------|
| R1 | **Harness 五件套可分离** | 上下文、工具、约束、验证、纠正；均可开关（为消融） | 无法区分模型弱 vs Harness 弱 |
| R2 | **约束优先于指导** | 能代码强制的不用「请遵守」文档；规则进 linter/CI/工具内校验 | Agent 走破坏性捷径仍「结果看起来对」 |
| R3 | **致命三要素 + 持久记忆放大器** | 私有数据 + 不可信内容 + 外联；记忆把攻击跨会话放大 | 全权限本地 Agent 无边界即高危 |
| R4 | **提议者-审核者** | 能力相近、家族不同；共享规则、关注点分叉；拒绝理由回灌轨迹；事前审批 / 事后**模态切换**验证 | 单模型自审同盲区；无反馈闭环 |
| R5 | **Sidecar 门控** | 与流式并行但门控单次调用；**只看结构化 tool 调用**；拒绝熔断→人工 | 话术越权；无限拒绝死循环 |
| R6 | **沙盒与出口** | 默认断网+白名单；凭证不进沙盒；CPU/内存/超时；超时返回结构化错误非静默杀 | 外泄通道或无限资源耗尽 |
| R7 | **命令语义解析** | 理解参数消费规则，非关键字黑名单 | `find -exec rm` / `curl -o crontab` 漏网 |
| R8 | **业务规则真值守门**（Ch5 τ-bench 式） | 政策事实只查库+服务端时钟；`expected_*` 仅 checklist/审计，不参与裁决 | 模型自报舱位/保险即可绕过取消政策 |
| R9 | **四层故障分类** | API / 工具 / 上下文 / 控制流（死循环、死亡螺旋） | 一律「重试」浪费配额 |
| R10 | **先分类再计数** | 可重试 vs 不可重试映射表；工具名+参数指纹；连续失败计数 | 参数非法仍原样重试千次 |
| R11 | **活性与完整性** | 长连接 idle watchdog；缺 tool result 配对时产品模式可修补、**训练模式禁止假配对** | 静默卡死；污染训练数据 |
| R12 | **恢复三级** | 静默重试（指数退避+抖动）→ 降级/接续/备用模 → 暴露用户；工具错变模型输入不终止会话 | 中间错误刷屏；或静默失败无纠 |
| R13 | **每路径熔断 + 全局上限** | 压缩 N 次失败放弃；权限分类失败回退人工；最大轮次/预算；错误路径禁用再调 LLM 的副作用 | 死亡螺旋（停→钩子再 LLM→再溢出） |
| R14 | **故障边界（并行）** | 失败只在依赖同一结果的并行批内级联中止，不杀父任务/独立调用 | 一文件缺失杀整任务 |
| R15 | **纠正原则（Ch1/5）** | 确认无法恢复前不暴露中间态；错误处理边界=整个恢复环 | 用户看到假失败/半成功 |
| R16 | **写后即时语法反馈** | 工具层自动 linter，结果进返回值 | 到测阶段才发现括号错 |
| R17 | **完成标准=验证通过** | Coding：测试通过而非「代码写完」；防过早终止 | 偷懒报告 done |
| R18 | **回退可靠** | Git/沙盒/快照；安全网内大胆试错 | 试错=生产不可逆 |
| R19 | **忠诚度显式** | 主人指令最高；外部内容降格为数据无指令效力 | 交涉/注入策反 |
| R20 | **信任下移数据层** | 高危不变量在 schema/运行时强制，不靠生成 handler 自觉 | AI 写的权限检查可漏 |

### 2.2 可靠性一句话

**可靠性不取决于模型不犯错，而取决于每类错误是否都有：检测 → 恢复 → 终止路径。**

### 2.3 Falsifiers（可靠性/纠错）

| 声称 | 可证伪条件 |
|------|------------|
| 「有安全审查」 | 高风险 bash 无 Sidecar/无 HITL；或 Sidecar 读 chain-of-thought 文本 |
| 「可恢复」 | 同一 tool+args 指纹连续失败无熔断；压缩失败仍无限压 |
| 「工具错误可纠」 | 幻觉工具名导致会话直接崩，未回结构化「工具不存在」 |
| 「政策不可绕过」 | 取消/退款工具信任模型传入的金额/日期/保险标志裁决 |
| 「沙盒」 | 仅 venv 无 FS/网络隔离却称 sandbox |
| 「完成有验收」 | 无测试/无状态检查即可 mark complete |
| 「并行安全」 | 一并行调用失败取消全部独立读操作 |
| 「生产可观测」 | 无 span/无参数结果日志，故障不可回放 |
| 「Harness 可消融」 | 特性无法独立关闭，无法证明组件真实贡献 |

### 2.4 与 evaluate→learn 的接口（给 L8）

```text
失败轨迹 → 分类(API/工具/上下文/控制流/政策)
         → 结构化诊断(非标量)
         → 候选修改(描述/Skill/约束/工具内校验/Harness)
         → 回归集 + 保留集验证
         → 可回滚发布
```

纠正层产出的应是**带证据的诊断**，不是只红灯清单。

## 3. 评估（Evaluation）— 第六章

### 3.1 必须存在的结构

| ID | 结构 | 定义/要点 | 缺了会怎样 |
|----|------|-----------|------------|
| E1 | **评估对象=Model+Harness** | 模型替换实验 vs 组件消融；瓶颈可分模型/Harness | 裸模分低就只换模 |
| E2 | **五要素环境** | Dataset / Env State / Tools(原子) / Rubric / Interaction Protocol | 不可复现或工具过粗（「解决用户问题」） |
| E3 | **双范式环境** | 工具调用型（可执行金标）；人机交互型（用户模拟+渐进透露） | 客服类用「一次给全信息」假任务 |
| E4 | **状态可重置** | 真实性与可控性平衡；训练/仿真需可靠 reset | 评估不可复现 |
| E5 | **数据集五挑战对策** | 明确↔开放；真实↔可控；多样系统；成本覆盖；**防泄漏** | 测记忆力非能力 |
| E6 | **可验证性设计** | 二元/格式匹配；FAIL_TO_PASS+PASS_TO_PASS；DB 状态+对话关键词+流程合规；环境深度检查 | 表面完成实质失败 |
| E7 | **层次难度/能力标签** | Level 或能力矩阵；失败可诊断指向（工具 vs 规划 vs 长程） | 只剩一个总分无法改 |
| E8 | **指标词典必分清** | 过程：合法率、工具正确率、路径效率、成本延迟；结果：成功率；**Pass@k vs Pass^k vs Best@k**；安全零容忍 | 用 Pass@k 当回归稳定性 |
| E9 | **轨迹+结果双覆盖** | 说了什么 vs 环境最终状态；防虚假承诺 | 「已退款」无工具成功/状态未变仍高分 |
| E10 | **Rubric 四准则** | 专家指导；全面+陷阱；权重/Veto；自包含可操作档次 | 抽象「深刻理解」不可复现 |
| E11 | **幻觉/安全否决** | 一票否决，不与礼貌/完整度互补 | 流畅假话赢过短准确 |
| E12 | **Judge 校准** | 金标集+kappa 门槛；长度偏差治理；多源异构防同源共谋；位置偏差交换顺序 | Goodhart：钻评分洞 |
| E13 | **人机模拟规范** | 渐进透露；不编造脚本外事实；事实锚定(grounding)；陷阱任务 | 用户模拟一次倒干净 |
| E14 | **统计显著性** | SE≈√(p(1-p)/n)；分差<噪声不切换；同批任务**配对/McNemar**；多重比较校正；多次 seed | 3% 分差当部署依据 |
| E15 | **可观测性→评估资产** | Trace/span（OTel/OpenInference）；失败脱敏入库回归；成本按任务维 | 评估集静态脱离生产 |
| E16 | **Benchmark→改进闭环** | 先查评测系统再动 Agent；单变量轮次；机制指标≠目标指标；护栏指标 | 基于失真信号改错方向 |
| E17 | **内部评估基建** | 消融总开关早期注入；AB 多臂；双层 feature flag；提示词可渲染快照+回归；隐私类型包装 | 特性债务不可测 |
| E18 | **成本四组对照** | 缓存×压缩独立开关同任务实测；禁止节省比例相加 | 高估优化收益 |
| E19 | **预算—能力曲线** | 多预算点（时间/token/工具步）非单点 | 短预算领先误外推长程 |
| E20 | **仿真桥接训练** | 验证器=可验证奖励；高吞吐+reset；评估题与训练严格隔离 | 污染评估/训练互污 |

### 3.2 Rubric / Judge 最小可用模板（must-exist 字段）

```yaml
dimensions:
  - name: ...
    weight: essential | important | optional | veto
    scoring: {档次: 可观察行为描述, 非抽象形容词}
edge_cases: [...]
veto: 幻觉/安全/虚假承诺等
calibration: 金标集 id、kappa 门槛、judge 模型族 ≠ agent 模型族（审计时）
```

### 3.3 Falsifiers（评估）

| 声称 | 可证伪条件 |
|------|------------|
| 「有评估体系」 | 无固定数据集/无重置/无协议终止条件 |
| 「测的是 Agent」 | 只测最终文本、不查工具日志与环境状态 |
| 「可靠」 | 只报 Pass@k 或单次 run；无 Pass^k / 无 seed 方差 |
| 「Rubric 客观」 | 档次全是「深刻/流畅」；无边界案例；幻觉非 veto |
| 「LLM Judge 可信」 | 无金标校准；Agent 与 Judge 同家族且无多源审计 |
| 「用户模拟真实」 | 首轮给出全部隐私信息与答案 |
| 「可防泄漏」 | 固定公开答案且无时间切割/参数化/canary |
| 「改进有因果」 | 一次堆多改动；或分数降先改 Agent 不查评分器/环境 |
| 「内部评估」 | 主特性不可关闭；提示词变更无回归 |
| 「成本优化有效」 | 仅引用分项节省百分比相加，无联合实测 |
| 「可上线切换模型」 | 分差落在 SE 噪声内仍全量切换 |

### 3.4 评估闭环（审计用骨架）

```text
环境(可重置) + 数据集(防泄漏/可验证)
    → 跑 Agent 得轨迹+终态
    → 过程指标 + 结果指标 + 安全否决
    → (可选) LLM-as-Judge + 校准
    → 统计检验 / 配对
    → 诊断(能力标签/失败簇)
    → 单变量改 Harness 或模型
```
